# Auth Invite Permissions Spec Input

認証、メンバー招待、権限管理の仕様を書くための入力です。
APIリファレンス、ユーザーヘルプ、運用手順書を生成しやすいように、操作ごとの入力、出力、エラー、権限、ログを分けます。

## 読み込むファイル

- constitution.md
- spec/000_shared_rules.md
- spec/001_boards.md
- spec/002_lists.md
- spec/003_cards.md

## 作成するファイル

- spec/011_auth.md
- spec/012_member_invite.md
- spec/013_permissions.md

## 認証の対象

- サインアップ
- ログイン
- ログアウト
- セッション確認
- 未認証時の401

## メンバー招待の対象

- ownerによる招待作成
- 招待リンクの発行
- 招待の承認
- 招待の再送
- 招待の失効

## 権限管理の対象

- owner、member、viewerの操作権限
- ownerによるロール変更
- 最後のownerを降格できない制約
- viewerの閲覧専用制約

## 入力制約

- emailはメールアドレス形式
- passwordは8〜200文字とし、英字、数字、記号をそれぞれ1文字以上含める
- nameは1〜100文字とする
- 招待の有効期限は7日
- ロールはowner、member、viewerのみ

## 異常系

- email重複は409
- 認証失敗は401
- 権限不足は403
- 存在しない招待は404
- 期限切れ招待は410
- 入力制約違反は422

## 非機能

- 認証、招待、権限変更は操作ログに残す
- パスワードはハッシュ化して保存する
- 認証失敗時に具体的な失敗理由を返さない
- このハンズオンでは既存のBoard・List・Cardデータを認証用データへ移行しない。認証を追加するときは新しいローカルDBで開始する。ボードを作成したユーザーを、そのボードのownerにする

## 出力ルール

- 指定した3ファイルだけを作成または更新する
- 指定した3ファイル以外を変更する必要がある場合は、変更理由とファイル名を示し、書き出す前に確認を受ける
- 各仕様には機能要件、受入条件、異常系、境界条件、バリデーション、権限境界、ログ、ドキュメント化に必要なユーザー操作、未決事項を分けて書く
- 不明点がある場合は、仕様を書き始める前に質問する
- 完了時に、作成または更新したファイルを一覧で報告する
