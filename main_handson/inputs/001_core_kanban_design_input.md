# Core Kanban Design Input

最初のカンバンアプリの設計を書くための入力です。

## 読み込むファイル

- constitution.md
- spec/000_shared_rules.md
- spec/001_boards.md
- spec/002_lists.md
- spec/003_cards.md

## 作成するファイル

- design/001_boards.md
- design/002_lists.md
- design/003_cards.md

## 設計に含めるもの

- Prismaモデル
- API設計
- 画面構成
- 状態遷移
- 権限チェック
- ログ方針
- テスト方針
- 実装順序

## 出力ルール

- 指定した3ファイルだけを作成または更新する
- 指定した3ファイル以外を変更する必要がある場合は、変更理由とファイル名を示し、書き出す前に確認を受ける
- APIごとに入力、出力、ステータスコード、権限、ログを分けて書く
- 実装順序では、依存関係、先に作る共通部品、後から接続する画面を分けて書く
- 実装で迷いそうな点は未決事項として分け、独断で決めない
- 仕様と矛盾する可能性がある場合は、矛盾する条件を挙げ、どちらを採用するか確認する
- 完了時に、作成または更新したファイルを一覧で報告する
