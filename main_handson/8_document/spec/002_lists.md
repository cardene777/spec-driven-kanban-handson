# リスト機能の仕様

## 概要

リスト (List) はボード内の列を表す。
本 file は、リストの表示、作成、名称編集、削除、並び替えの仕様を定義する。
共通ルールは `spec/000_shared_rules.md`、リストが属するボードの仕様は `spec/001_boards.md` を参照する。

## 対象データ

`List` エンティティのフィールド。

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | 文字列 | リストを一意に識別する ID |
| `boardId` | 文字列 | 所属するボードの ID |
| `title` | 文字列 | リスト名 (1〜100 文字) |
| `order` | 数値 | 同一ボード内での並び順 (昇順) |
| `createdAt` | ISO8601 UTC | 作成日時 |
| `updatedAt` | ISO8601 UTC | 更新日時 |

## 機能要件

### 表示

- ボード詳細画面 (`/boards/[id]`) の本体に、同一 `boardId` のリストを `order` 昇順で横並び表示する。
- 各リストは `title` と、そのリストに属するカード一覧 (`spec/003_cards.md`) を表示する。
- リストが 0 件のとき、共通ルールに従い空状態を表示する。
- 各リストにリスト内カード新規作成の導線を配置する (詳細は `spec/003_cards.md` と `ui-design/`)。
- ボード詳細画面上にリスト新規作成の導線を配置する (詳細は `ui-design/`)。

### 操作: リスト作成

- ボード詳細画面から新規作成する。
- 入力項目は `title` のみ (`boardId` は URL から特定する)。
- 作成後、新規リストは同一 `boardId` 内の末尾に配置される (`order` は同一スコープの末尾)。

### 操作: リスト名編集

- リストヘッダから `title` を編集する。
- 変更対象は `title` のみ。

### 操作: リスト削除

- リストヘッダの操作メニューから実行する。
- 削除操作は明示的な確認 (確認ダイアログ等) を伴う。UI 詳細は `ui-design/` で決める。
- 削除時、`spec/000_shared_rules.md § カスケード削除` に従い、配下のカードを全て削除する。

### 操作: リスト並び替え

- 同一ボード内でリストの並び順を変更する。
- ドラッグアンドドロップ等の操作方法は `ui-design/` で決める。本 spec は API を規定する。
- 並び替え対象リストと、そのリストを移動する新しい位置 (`toIndex`) を受け取る。
- ボード境界を跨いだリスト移動は本 spec の対象外とする (`§ 未決事項` 参照)。
- 並び替えのみを行った場合でも、対象リストの `updatedAt` を更新する。

## API

| メソッド | パス | 用途 | 必要権限 |
|---|---|---|---|
| `GET` | `/api/boards/{boardId}/lists` | 指定ボード内のリスト一覧を取得 | 対象ボードの `viewer` 以上 |
| `POST` | `/api/boards/{boardId}/lists` | 指定ボードにリストを新規作成 | 対象ボードの `member` 以上 |
| `PATCH` | `/api/lists/{listId}` | リスト名を更新 | 対象ボードの `member` 以上 |
| `DELETE` | `/api/lists/{listId}` | リストを削除 | 対象ボードの `member` 以上 |
| `PATCH` | `/api/lists/{listId}/order` | リストを同一ボード内で並び替え | 対象ボードの `member` 以上 |

- レスポンス形式と認証チェック順序は `spec/000_shared_rules.md` に従う。
- 一覧 API のレスポンスは `{ items: List[] }`、単体 API のレスポンスは `List` オブジェクト。
- 並び替え API のリクエスト body には移動先位置を示すフィールドを含める (フィールド名と表現形式は設計工程で決める。本 spec では「同一ボード内での新しい位置」 の指定が可能なこと、および「同一ボード内で order が一意に保たれること」 を要求する)。

## 受入条件

- [ ] ボード詳細画面を開くと、そのボードのリストが `order` 昇順で横並び表示される。
- [ ] リストが 0 件のとき、ボード詳細画面のリスト領域に空状態が表示される。
- [ ] リスト新規作成導線からタイトル 1〜100 文字を入力してリストを作成すると、同一ボードの末尾に追加される。
- [ ] リストヘッダからタイトルを編集して保存すると、画面上で新タイトルが反映される。
- [ ] リストヘッダから削除を実行し確認すると、そのリストは画面から消える。
- [ ] リスト削除時、そのリストに紐づく全カードが削除されている。
- [ ] リストを別の位置に並び替えると、他リストの `order` も再計算され、同一ボード内で順序が一意に保たれる。
- [ ] `viewer` ロールのユーザーがリスト作成、編集、削除、並び替え API を呼ぶと `403` が返る。
- [ ] 未ログインユーザーが `/api/boards/{boardId}/lists` 以下を呼ぶと `401` が返る。
- [ ] 存在しない `boardId` または `listId` を指定した API 呼出は `404` を返す。

## 異常系

`spec/000_shared_rules.md § HTTP ステータスコード` と `§ Route Handler の入口チェック順序` に従う。

### 認証、権限、存在チェック

| 状況 | ステータス | 補足 |
|---|---|---|
| 未ログインで API 呼出 | `401` | 全 API 共通 |
| 存在しない `boardId` を指定 | `404` | 一覧、作成 API |
| 存在しない `listId` を指定 | `404` | 更新、削除、並び替え API |
| 閲覧権限 (`viewer` 以上) のないボード配下のリストを指定 | `404` | 存在有無を漏らさないため `404` に統一 |
| `viewer` ロールのユーザーがリスト作成、編集、削除、並び替え API を呼ぶ | `403` | 認証済み、閲覧可の状態が前提 |

### バリデーションエラー

| 状況 | ステータス | フィールド | メッセージ例 |
|---|---|---|---|
| `title` 未指定または空文字 | `422` | `title` | `required` |
| `title` が 100 文字超過 | `422` | `title` | `too_long` |
| `title` が文字列型でない | `422` | `title` | `invalid_type` |
| 並び替えの移動先位置が数値でない、または負数 | `422` | (位置指定フィールド) | `invalid_position` |
| 並び替えの移動先位置が同一ボード内リスト数を超える | `422` | (位置指定フィールド) | `out_of_range` |

### 画面レベル

- リスト作成、編集、削除、並び替えの API が `403` を返した場合、「操作権限がありません」 相当の表示を行う。
- 並び替え途中に API が失敗した場合、UI 上の並び順を元の状態に戻す (ロールバック挙動)。

## 境界条件

- `title` = 1 文字 (下限ちょうど): 受け付ける。
- `title` = 100 文字 (上限ちょうど): 受け付ける。
- `title` = 101 文字: `422` を返す。
- `title` = 0 文字 (空文字): `422` を返す。
- `title` トリム後 0 文字: `422` を返す。
- リスト 0 件: 一覧 API は `{ items: [] }` を 200 で返す。
- 同一 `boardId` 内で `title` が重複してよい (title は一意制約なし)。
- 同一ボードにリストが 1 件しかない状態で並び替え API を呼んだ場合、移動先位置が `0` なら 200 で成功、それ以外は `422`。
- リスト削除時、そのリストが同一ボード内の最後の 1 件であってもボードは残る (ボードは削除しない)。
- 同一 `boardId` 内で `order` は一意である。
- 別 `boardId` のリストが同じ `order` 値を持ってよい (`order` の一意性は `boardId` 単位)。

## バリデーション

| フィールド | ルール |
|---|---|
| `title` | 文字列。トリム後 1〜100 文字。トリム後 0 または 101 以上で `422`。|
| `boardId` (URL パラメータ) | 文字列。フォーマット検証は設計工程で決定 (現時点では「存在すれば取得、存在しなければ 404」)。|
| `listId` (URL パラメータ) | 同上。|
| 並び替え移動先位置 | 0 以上の整数。同一ボード内のリスト数を上限とする。上限超過または負数で `422`。|

作成 API では `id` / `order` / `createdAt` / `updatedAt` はクライアントから受け取らない (サーバー側で生成、設定する)。
更新 API (`PATCH /api/lists/{listId}`) で受け付けるのは `title` のみ。
並び替え API (`PATCH /api/lists/{listId}/order`) で受け付けるのは移動先位置のみ。

## 権限境界

`spec/000_shared_rules.md § 権限マトリクス` に従う。リストに閉じた表を再掲する。

| 操作 | 必要権限 | 権限不足時の挙動 |
|---|---|---|
| リスト一覧取得 (`GET /api/boards/{boardId}/lists`) | 対象ボードの `viewer` 以上 | 未ログイン `401`、閲覧不可 `404` |
| リスト作成 (`POST /api/boards/{boardId}/lists`) | 対象ボードの `member` 以上 | 未ログイン `401`、`viewer` は `403`、閲覧不可 `404` |
| リスト編集 (`PATCH /api/lists/{listId}`) | 対象ボードの `member` 以上 | 未ログイン `401`、`viewer` は `403`、閲覧不可 `404` |
| リスト削除 (`DELETE /api/lists/{listId}`) | 対象ボードの `member` 以上 | 未ログイン `401`、`viewer` は `403`、閲覧不可 `404` |
| リスト並び替え (`PATCH /api/lists/{listId}/order`) | 対象ボードの `member` 以上 | 未ログイン `401`、`viewer` は `403`、閲覧不可 `404` |

## 非機能要件

`spec/000_shared_rules.md § 非機能要件` に従う。リスト固有の追加要件は無し。
並び替え API も書き込み API として P95 300ms 以内の目標を適用する。

## 未決事項

- リストを別ボードに移動する機能は本 spec の対象外。将来別 spec で扱う。
- 並び替え API のリクエスト body 表現 (`toIndex` 直指定 / `beforeListId` 指定 / `order` 直接指定) は設計工程で決める。
- 並び替え時の楽観的更新 (UI 先行更新 → API 失敗時ロールバック) の挙動詳細は `ui-design/` と設計工程で決める。
- ドラッグアンドドロップの実装ライブラリ選定は設計工程で決める。
