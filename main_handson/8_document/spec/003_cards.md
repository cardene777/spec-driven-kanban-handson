# カード機能の仕様

## 概要

カード (Card) はタスクを表す項目である。
本 file は、カードの表示、作成、タイトル編集、説明文編集、削除、並び替え、およびカード詳細モーダルの基本構造の仕様を定義する。
共通ルールは `spec/000_shared_rules.md`、カードが属するリストの仕様は `spec/002_lists.md`、リストが属するボードの仕様は `spec/001_boards.md` を参照する。

## 対象データ

`Card` エンティティのフィールド。

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | 文字列 | カードを一意に識別する ID |
| `listId` | 文字列 | 所属するリストの ID |
| `title` | 文字列 | カードタイトル (1〜200 文字) |
| `description` | 文字列 | カード説明文 (0〜2000 文字、空文字許容) |
| `order` | 数値 | 同一リスト内での並び順 (昇順) |
| `createdAt` | ISO8601 UTC | 作成日時 |
| `updatedAt` | ISO8601 UTC | 更新日時 |

## 機能要件

### 表示

- 各リスト内に、同一 `listId` のカードを `order` 昇順で縦並び表示する。
- カード行は `title` を表示する (`description` はカード詳細モーダルで表示する)。
- カードが 0 件のリストは、リスト内に空状態を表示する (詳細は `ui-design/`)。
- 各リストにカード新規作成の導線を配置する。

### 操作: カード作成

- 各リスト内の新規作成導線から作成する。
- 入力項目は `title` のみ (`description` は空文字で初期化)。
- 作成後、新規カードは同一 `listId` 内の末尾に配置される (`order` は同一スコープの末尾)。

### 操作: カードタイトル編集

- カード詳細モーダル、またはカード行のインライン編集から `title` を編集する (UI 詳細は `ui-design/`)。
- 変更対象は `title` のみ。

### 操作: カード説明文編集

- カード詳細モーダルから `description` を編集する。
- 変更対象は `description` のみ。
- 空文字での保存を許容する。

### 操作: カード削除

- カード詳細モーダルから実行する。
- 削除操作は明示的な確認 (確認ダイアログ等) を伴う。UI 詳細は `ui-design/` で決める。

### 操作: カード並び替え

- カードは以下 2 種類の並び替えを行う。
  - 同一リスト内での順序変更
  - 別リストへの移動 (同一ボード内の別 `listId` へ)
- 別ボードのリストへの移動は本 spec の対象外とする (`§ 未決事項` 参照)。
- ドラッグアンドドロップ等の操作方法は `ui-design/` で決める。本 spec は API を規定する。
- 並び替え対象カード、移動先 `listId`、移動先位置を受け取る。
- 並び替えのみを行った場合でも、対象カードの `updatedAt` を更新する。

### カード詳細モーダルの基本構造

- カード行のクリックでモーダルを開く。
- モーダルには以下の要素を配置する。
  - `title` の表示と編集
  - `description` の表示と編集
  - `createdAt` と `updatedAt` の表示
  - カード削除の導線
  - モーダルを閉じる導線
- モーダルは URL に紐づけない (パス変更を伴わない、画面上のオーバーレイ表現) を初期方針とする。URL 表現との紐付けは `ui-design/` で最終決定する。
- 将来拡張 (担当者、期限、コメント) の配置枠を意識するが、本 spec ではそれらの機能自体は対象外。

## API

| メソッド | パス | 用途 | 必要権限 |
|---|---|---|---|
| `GET` | `/api/lists/{listId}/cards` | 指定リスト内のカード一覧を取得 | 対象ボードの `viewer` 以上 |
| `GET` | `/api/cards/{cardId}` | 指定カードの詳細を取得 | 対象ボードの `viewer` 以上 |
| `POST` | `/api/lists/{listId}/cards` | 指定リストにカードを新規作成 | 対象ボードの `member` 以上 |
| `PATCH` | `/api/cards/{cardId}` | カードタイトルまたは説明文を更新 | 対象ボードの `member` 以上 |
| `DELETE` | `/api/cards/{cardId}` | カードを削除 | 対象ボードの `member` 以上 |
| `PATCH` | `/api/cards/{cardId}/order` | カードを並び替え (同一リスト内、または同一ボード内の別リストへ移動) | 対象ボードの `member` 以上 |

- レスポンス形式と認証チェック順序は `spec/000_shared_rules.md` に従う。
- 一覧 API のレスポンスは `{ items: Card[] }`、単体 API のレスポンスは `Card` オブジェクト。
- `PATCH /api/cards/{cardId}` は `title` と `description` を任意に受け取る (どちらか一方の指定でも可)。両方未指定の場合は `422`。
- 並び替え API のリクエスト body には「移動先 `listId`」 と「移動先位置」 を含める (フィールド名と表現形式は設計工程で決める)。

## 受入条件

- [ ] リスト内のカードが `order` 昇順で縦並び表示される。
- [ ] カードが 0 件のリストは空状態を表示する。
- [ ] カード新規作成導線からタイトル 1〜200 文字を入力してカードを作成すると、同一リストの末尾に追加され、`description` は空文字となる。
- [ ] カード行をクリックすると詳細モーダルが開き、`title` / `description` / `createdAt` / `updatedAt` / 削除導線 / 閉じる導線が表示される。
- [ ] 詳細モーダルで `title` を編集して保存すると、カード行と詳細モーダルの両方で新タイトルが反映される。
- [ ] 詳細モーダルで `description` を 0〜2000 文字の範囲で編集して保存すると、詳細モーダルで新説明文が反映される。
- [ ] 詳細モーダルから削除を実行し確認すると、そのカードは画面から消え、モーダルは閉じる。
- [ ] カードを同一リスト内で並び替えると、同一リスト内で `order` が再計算され、順序が一意に保たれる。
- [ ] カードを別リスト (同一ボード内) に移動すると、移動先リストの指定位置に配置され、移動元リストの残カードの `order` が詰められる。
- [ ] `viewer` ロールのユーザーがカード作成、編集、削除、並び替え API を呼ぶと `403` が返る。
- [ ] 未ログインユーザーが `/api/lists/{listId}/cards` 以下または `/api/cards/{cardId}` 以下を呼ぶと `401` が返る。
- [ ] 存在しない `listId` または `cardId` を指定した API 呼出は `404` を返す。

## 異常系

`spec/000_shared_rules.md § HTTP ステータスコード` と `§ Route Handler の入口チェック順序` に従う。

### 認証、権限、存在チェック

| 状況 | ステータス | 補足 |
|---|---|---|
| 未ログインで API 呼出 | `401` | 全 API 共通 |
| 存在しない `listId` を指定 | `404` | 一覧、作成 API |
| 存在しない `cardId` を指定 | `404` | 詳細、更新、削除、並び替え API |
| 閲覧権限 (`viewer` 以上) のないボード配下のカードを指定 | `404` | 存在有無を漏らさないため `404` に統一 |
| 並び替え API で移動先 `listId` が別ボードに属する | `404` | 別ボードのリストは「アクセスできないリソース」 として扱い `404` を返す |
| `viewer` ロールのユーザーがカード作成、編集、削除、並び替え API を呼ぶ | `403` | 認証済み、閲覧可の状態が前提 |

### バリデーションエラー

| 状況 | ステータス | フィールド | メッセージ例 |
|---|---|---|---|
| `title` 未指定または空文字 (作成時、更新時に指定) | `422` | `title` | `required` |
| `title` が 200 文字超過 | `422` | `title` | `too_long` |
| `title` が文字列型でない | `422` | `title` | `invalid_type` |
| `description` が 2000 文字超過 | `422` | `description` | `too_long` |
| `description` が文字列型でない | `422` | `description` | `invalid_type` |
| 更新 API で `title` と `description` の両方が未指定 | `422` | (body 全体) | `no_updates` |
| 並び替えの移動先位置が数値でない、または負数 | `422` | (位置指定フィールド) | `invalid_position` |
| 並び替えの移動先位置が対象リスト内カード数を超える | `422` | (位置指定フィールド) | `out_of_range` |

### 画面レベル

- カード詳細モーダルで API が `403` を返した場合、「操作権限がありません」 相当の表示を行う。
- カード詳細モーダルで API が `404` を返した場合、「カードが見つかりません」 相当の表示を行い、モーダルを閉じる。
- 並び替え途中に API が失敗した場合、UI 上の並び順を元の状態に戻す (ロールバック挙動)。

## 境界条件

### `title`

- 1 文字 (下限ちょうど): 受け付ける。
- 200 文字 (上限ちょうど): 受け付ける。
- 201 文字: `422` を返す。
- 0 文字 (空文字): `422` を返す。
- トリム後 0 文字: `422` を返す。

### `description`

- 0 文字 (空文字): 受け付ける (下限)。
- 2000 文字 (上限ちょうど): 受け付ける。
- 2001 文字: `422` を返す。
- `description` は空文字を許容するため、トリム判定は行わない (先頭、末尾の空白もそのまま保存する)。

### 並び替え

- 同一リスト内でカードが 1 件しかない状態で並び替え API を呼んだ場合、移動先位置が `0` かつ移動先 `listId` が同一なら 200 で成功、それ以外は `422` または該当する `404` を返す。
- カードを別リストに移動した後、移動元リストの残カードの `order` は詰めて再計算する (連番、または連番相当を保つ)。
- 同一 `listId` 内で `order` は一意である。
- 別 `listId` のカードが同じ `order` 値を持ってよい (`order` の一意性は `listId` 単位)。

### その他

- カード 0 件: 一覧 API は `{ items: [] }` を 200 で返す。
- 同一 `listId` 内で `title` が重複してよい (title は一意制約なし)。

## バリデーション

| フィールド | ルール |
|---|---|
| `title` | 文字列。トリム後 1〜200 文字。トリム後 0 または 201 以上で `422`。作成時は必須、更新時は指定された場合のみ検証。|
| `description` | 文字列。0〜2000 文字。2001 以上で `422`。空文字を許容し、トリム判定は行わない。|
| `listId` (URL パラメータ) | 文字列。フォーマット検証は設計工程で決定 (現時点では「存在すれば取得、存在しなければ 404」)。|
| `cardId` (URL パラメータ) | 同上。|
| 並び替え移動先位置 | 0 以上の整数。移動先リスト内カード数を上限とする (同一リスト内での並び替えは自リストを除いた件数、別リストへの移動は移動先リストのカード数)。上限超過または負数で `422`。|

作成 API では `id` / `order` / `createdAt` / `updatedAt` はクライアントから受け取らない (サーバー側で生成、設定する)。
更新 API (`PATCH /api/cards/{cardId}`) で受け付けるのは `title` / `description` のみ。
並び替え API (`PATCH /api/cards/{cardId}/order`) で受け付けるのは移動先 `listId` と移動先位置のみ。

## 権限境界

`spec/000_shared_rules.md § 権限マトリクス` に従う。カードに閉じた表を再掲する。

| 操作 | 必要権限 | 権限不足時の挙動 |
|---|---|---|
| カード一覧取得 (`GET /api/lists/{listId}/cards`) | 対象ボードの `viewer` 以上 | 未ログイン `401`、閲覧不可 `404` |
| カード詳細取得 (`GET /api/cards/{cardId}`) | 対象ボードの `viewer` 以上 | 未ログイン `401`、閲覧不可 `404` |
| カード作成 (`POST /api/lists/{listId}/cards`) | 対象ボードの `member` 以上 | 未ログイン `401`、`viewer` は `403`、閲覧不可 `404` |
| カード編集 (`PATCH /api/cards/{cardId}`) | 対象ボードの `member` 以上 | 未ログイン `401`、`viewer` は `403`、閲覧不可 `404` |
| カード削除 (`DELETE /api/cards/{cardId}`) | 対象ボードの `member` 以上 | 未ログイン `401`、`viewer` は `403`、閲覧不可 `404` |
| カード並び替え (`PATCH /api/cards/{cardId}/order`) | 対象ボードの `member` 以上、かつ移動先リストが同一ボード内であること | 未ログイン `401`、`viewer` は `403`、別ボードのリスト指定は `404` |

## 非機能要件

`spec/000_shared_rules.md § 非機能要件` に従う。カード固有の追加要件は無し。
並び替え API も書き込み API として P95 300ms 以内の目標を適用する。

## 未決事項

- 別ボードのリストへのカード移動は本 spec の対象外。将来別 spec で扱う。
- 並び替え API のリクエスト body 表現 (`toIndex` + `toListId` 直指定 / `beforeCardId` 指定 / `order` 直接指定) は設計工程で決める。
- 並び替え時の楽観的更新 (UI 先行更新 → API 失敗時ロールバック) の挙動詳細は `ui-design/` と設計工程で決める。
- カード詳細モーダルの URL 表現 (`?card={cardId}` クエリ紐付け vs 状態のみ) は `ui-design/` で決める。
- カード詳細モーダルの担当者、期限、コメント欄の配置は本 spec の対象外 (別 spec)。
- `description` に対する Markdown レンダリングの有無は本 spec の対象外とし、初期実装は plain text 表示とする。Markdown 対応は別 spec で扱う。
