# ラベル機能の仕様

## 概要

本 file はラベル (Label) の仕様を定義する。
ラベルはボード単位で管理し、カードに 0 個以上付与できる分類タグである。
本 spec が扱う操作は、ボード単位のラベル作成 / 編集 / 削除、およびカードへの付与 / 解除である。
共通ルールは `spec/000_shared_rules.md`、ボード仕様は `spec/001_boards.md`、カード仕様は `spec/003_cards.md`、カード詳細モーダルの配置は `spec/005_card_detail.md § カード詳細モーダルの拡張構造` を参照する。

## 既存仕様との関係

- 本 spec は `spec/003_cards.md` および `spec/005_card_detail.md` に対する追補である。
- `spec/005_card_detail.md § カード詳細モーダルの拡張構造` の「ラベル領域」 は本 spec で表示、操作方針を確定させる。
- 検索とラベルによる絞り込みは `spec/008_search_filter.md` で扱う。

## 対象データ

### Label エンティティ

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | 文字列 | ラベルを一意に識別する ID |
| `boardId` | 文字列 | 所属するボードの ID (ラベルはボード単位) |
| `name` | 文字列 | ラベル名 (1〜50 文字) |
| `color` | 文字列 (列挙値) | ラベル色。事前定義された色パレットからのみ選択可 |
| `createdAt` | ISO8601 UTC | 作成日時 |
| `updatedAt` | ISO8601 UTC | 更新日時 |

### 事前定義された色パレット

`color` は次の 8 色のいずれかを取る。列挙外の値は `422`。

| 値 | 想定用途 |
|---|---|
| `red` | 緊急、警告 |
| `orange` | 注意、進行中 |
| `yellow` | 保留、確認待ち |
| `green` | 正常、完了、承認 |
| `blue` | 情報、通常 |
| `purple` | 特別、実験 |
| `pink` | デザイン、UX |
| `gray` | その他、未分類 |

- 具体的な CSS カラーコードは `ui-design/` で決める。本 spec は識別子のみを固定する。

### CardLabel 関連 (中間表現)

- カードとラベルは多対多の関連を持つ。
- 1 枚のカードに同一ラベルを重複付与できない (関連の一意性は `(cardId, labelId)`)。
- 関連の内部表現 (中間テーブル / JSON 配列 / 他) は設計工程で決める。本 spec では以下のみを要求する。
  - 対象カードに紐づくラベル群を取得できる。
  - 対象ラベルが付与されているカード群を取得できる (絞り込み用途、`spec/008_search_filter.md`)。
  - 付与、解除の順序と重複排除が保証される。

## 機能要件

### 操作: ラベル作成 (ボード単位)

- ボードのラベル管理画面 (`§ 画面` 参照) から実行する。
- 入力項目は `name` と `color`。
- 作成後、対象ボードのラベル一覧に追加される。
- 同一ボード内で `name` の重複を許容しない (作成時と編集時にチェック)。

### 操作: ラベル編集

- ラベル管理画面のラベル行、またはカード詳細モーダルのラベル領域から編集導線を実行する。
- 変更対象は `name` と `color` (両方または片方)。
- 編集後、対象ラベルが付与されている全カードで表示が即時反映される。
- 同一ボード内で `name` の重複が発生する編集は不可 (`422`)。

### 操作: ラベル削除

- ラベル管理画面から実行する。
- 削除操作は明示的な確認 (確認ダイアログ等) を伴う。UI 詳細は `ui-design/` で決める。
- 削除時、対象ラベルの全カードへの付与関連 (`CardLabel`) を同時に解除する (カスケード削除の一種)。
- カード自体は削除しない。

### 操作: カードへのラベル付与

- カード詳細モーダルのラベル領域から実行する (`spec/005_card_detail.md § カード詳細モーダルの拡張構造`)。
- 対象カードが属するボードに紐づくラベルのみ付与可能。
- 1 枚のカードに複数ラベル (0 個以上) を付与できる。
- 既に付与済みのラベルを再度付与しようとした場合は `200` で成功、状態は変わらない (idempotent)。
- 付与操作は対象カードの `updatedAt` を更新する。

### 操作: カードからのラベル解除

- カード詳細モーダルのラベル領域から実行する。
- 対象カードに付与されていないラベルを解除しようとした場合は `200` で成功、状態は変わらない (idempotent)。
- 解除操作は対象カードの `updatedAt` を更新する。

## 画面

- ラベル管理画面: ボード詳細画面 (`/boards/[id]`) からの導線で開くパネルまたは画面 (詳細は `ui-design/`)。
  - 対象ボードのラベル一覧を表示する (並び順は `name` 昇順、`createdAt` 昇順で解決)。
  - 各行にラベル `name`、`color` プレビュー、編集導線、削除導線を配置する。
  - 新規作成の導線を配置する。
  - ラベル 0 件時は空状態を表示する。
- カード詳細モーダルのラベル領域: 付与済みラベルのバッジ一覧と、付与 / 解除の導線 (トグル型セレクタ想定、詳細は `ui-design/`)。
  - 付与可能な全ラベルの中から、付与済み / 未付与を視覚的に区別する。
  - ラベル 0 件のカードは「ラベルなし」 相当の空状態を表示する (文言は `ui-design/`)。

## API

| メソッド | パス | 用途 | 必要権限 |
|---|---|---|---|
| `GET` | `/api/boards/{boardId}/labels` | 指定ボードのラベル一覧を取得 | 対象ボードの `viewer` 以上 |
| `POST` | `/api/boards/{boardId}/labels` | 指定ボードにラベルを新規作成 | 対象ボードの `member` 以上 |
| `PATCH` | `/api/labels/{labelId}` | ラベル名または色を更新 | 対象ボードの `member` 以上 |
| `DELETE` | `/api/labels/{labelId}` | ラベルを削除 (付与関連も解除) | 対象ボードの `member` 以上 |
| `GET` | `/api/cards/{cardId}/labels` | 指定カードに付与されているラベル一覧を取得 | 対象ボードの `viewer` 以上 |
| `POST` | `/api/cards/{cardId}/labels/{labelId}` | 指定ラベルをカードに付与 | 対象ボードの `member` 以上 |
| `DELETE` | `/api/cards/{cardId}/labels/{labelId}` | 指定ラベルをカードから解除 | 対象ボードの `member` 以上 |

- レスポンス形式と認証チェック順序は `spec/000_shared_rules.md` に従う。
- 一覧 API のレスポンスは `{ items: Label[] }`、単体 API のレスポンスは `Label` オブジェクト。
- `POST /api/boards/{boardId}/labels` と `PATCH /api/labels/{labelId}` のリクエスト body は `{ "name": <文字列>, "color": <文字列> }`。`PATCH` は `name` と `color` のいずれか片方または両方 (両方未指定は `422`)。
- `POST /api/cards/{cardId}/labels/{labelId}` および `DELETE /api/cards/{cardId}/labels/{labelId}` は body を要求せず、成功時は 204 (body なし) を返す。
- `DELETE /api/labels/{labelId}` は成功時に 204 を返す。

## 受入条件

- [ ] `member` 以上のユーザーがラベル管理画面から `name` 1〜50 文字と `color` (8 色のいずれか) を入力してラベルを作成すると、対象ボードのラベル一覧に追加される。
- [ ] 同一ボード内で既存ラベルと同じ `name` で作成しようとすると `422` (`duplicate_name`) が返る。
- [ ] `member` 以上のユーザーがラベルの `name` または `color` を編集して保存すると、対象ラベルが付与されている全カードで表示が反映される。
- [ ] `member` 以上のユーザーがラベル削除を実行し確認すると、ラベル一覧から消え、全カードから該当ラベルの付与関連も解除される。
- [ ] `member` 以上のユーザーがカード詳細モーダルからラベル付与を実行すると、対象カードのラベル領域にバッジが追加され、`GET /api/cards/{cardId}/labels` の返却一覧に含まれる。
- [ ] 既に付与済みのラベルを再度付与しても `200` (または 204) が返り、重複追加されない。
- [ ] `member` 以上のユーザーがラベル解除を実行すると、対象カードのラベル領域からバッジが消える。
- [ ] 付与されていないラベルを解除しても `200` (または 204) が返り、状態は変わらない。
- [ ] `viewer` ロールのユーザーがラベル作成、編集、削除、付与、解除 API を呼ぶと `403` が返る。
- [ ] 未ログインユーザーが本 spec のいずれの API を呼んでも `401` が返る。
- [ ] 存在しない `boardId` / `labelId` / `cardId` を指定した API 呼出は `404` を返す。
- [ ] 別ボードに属するラベルをカードに付与しようとすると `404` (`label_not_in_board`) が返る。
- [ ] ラベル `color` に列挙外の値を指定すると `422` (`invalid_color`) が返る。

## 異常系

`spec/000_shared_rules.md § HTTP ステータスコード` と `§ Route Handler の入口チェック順序` に従う。

### 認証、権限、存在チェック

| 状況 | ステータス | 補足 |
|---|---|---|
| 未ログインで本 spec の API 呼出 | `401` | 全 API 共通 |
| 存在しない `boardId` を指定 | `404` | 一覧、作成 API |
| 存在しない `labelId` を指定 | `404` | 編集、削除、付与、解除 API |
| 存在しない `cardId` を指定 | `404` | カード配下のラベル一覧、付与、解除 API |
| 閲覧権限 (`viewer` 以上) のないボード配下の `labelId` / `cardId` を指定 | `404` | 存在有無を漏らさないため `404` に統一 |
| カードとラベルが別ボードに属する組み合わせで付与 API 呼出 | `404` | 別ボードのリソースは「アクセスできないリソース」 として `404` |
| `viewer` ロールがラベル作成、編集、削除、付与、解除 API を呼ぶ | `403` | 認証済み、閲覧可の状態が前提 |

### バリデーションエラー

| 状況 | ステータス | フィールド | メッセージ例 |
|---|---|---|---|
| `name` 未指定またはトリム後 0 文字 (作成時、編集時に指定) | `422` | `name` | `required` |
| `name` が 50 文字超過 | `422` | `name` | `too_long` |
| `name` が文字列型でない | `422` | `name` | `invalid_type` |
| `name` が同一ボード内で既存ラベルと重複 (作成 / 編集) | `422` | `name` | `duplicate_name` |
| `color` 未指定 (作成時) | `422` | `color` | `required` |
| `color` が事前定義された 8 色以外 | `422` | `color` | `invalid_color` |
| `color` が文字列型でない | `422` | `color` | `invalid_type` |
| 編集 API で `name` と `color` の両方が未指定 | `422` | (body 全体) | `no_updates` |

### 画面レベル

- ラベル管理画面の API が `403` を返した場合、「操作権限がありません」 相当の表示を行う。
- カード詳細モーダルのラベル領域の付与 / 解除 API が失敗した場合、対象ラベルの操作前状態に戻す (ロールバック挙動)。
- ラベル削除中に対象ラベルが付与されているカードが表示中の場合、削除完了後にラベル領域から該当バッジを取り除く (再取得または楽観的更新は `ui-design/` で決める)。

## 境界条件

### `name`

- 1 文字 (下限ちょうど): 受け付ける。
- 50 文字 (上限ちょうど): 受け付ける。
- 51 文字: `422` を返す。
- 0 文字 (空文字): `422` を返す。
- トリム後 0 文字 (空白のみ): `422` を返す。
- 同一ボード内での `name` 一意性判定は、大文字小文字を区別する (SQLite の `TEXT` デフォルト挙動と整合)。設計工程で正規化 (`NFC`) の要否を決める。

### `color`

- 8 色のいずれか: 受け付ける。
- 大文字表記 (`RED` 等): `422` (`invalid_color`)。列挙値は小文字固定。
- 空文字、`null`: `422` (`required` または `invalid_type`)。

### ラベル付与 / 解除

- 対象カードのラベル 0 件から 1 件目の付与: `204` で成功。
- 既に 1 件付与された状態での 2 件目付与: `204` で成功、両ラベルが付与されている状態になる。
- 付与済みラベルの再付与: `204` で成功、状態は変わらない (idempotent)。
- 未付与ラベルの解除: `204` で成功、状態は変わらない (idempotent)。
- 対象カードに付与可能なラベル数の上限は本 spec では設けない。

### 一覧

- ラベル 0 件: 一覧 API は `{ items: [] }` を 200 で返す。
- カード配下のラベル 0 件: `GET /api/cards/{cardId}/labels` は `{ items: [] }` を 200 で返す。

## バリデーション

| フィールド | ルール |
|---|---|
| `name` | 文字列。トリム後 1〜50 文字。トリム後 0 または 51 以上で `422`。同一ボード内で一意 (重複時 `duplicate_name`)。 |
| `color` | 文字列。`red` / `orange` / `yellow` / `green` / `blue` / `purple` / `pink` / `gray` のいずれか。列挙外で `invalid_color`。 |
| `boardId` / `labelId` / `cardId` (URL パラメータ) | 文字列。存在しないと `404`。閲覧権限がないと `404`。 |

- 作成 API では `id` / `boardId` (URL から特定) / `createdAt` / `updatedAt` はクライアントから受け取らない。
- 編集 API で受け付けるのは `name` と `color` のみ (両方未指定は `422`)。

## 権限境界

`spec/000_shared_rules.md § 権限マトリクス` に本 spec 追加操作を統合した表。

| 操作 | 必要権限 | 権限不足時の挙動 |
|---|---|---|
| ラベル一覧取得 (`GET /api/boards/{boardId}/labels`) | 対象ボードの `viewer` 以上 | 未ログイン `401`、閲覧不可 `404` |
| ラベル作成 (`POST /api/boards/{boardId}/labels`) | 対象ボードの `member` 以上 | 未ログイン `401`、`viewer` は `403`、閲覧不可 `404` |
| ラベル編集 (`PATCH /api/labels/{labelId}`) | 対象ボードの `member` 以上 | 未ログイン `401`、`viewer` は `403`、閲覧不可 `404` |
| ラベル削除 (`DELETE /api/labels/{labelId}`) | 対象ボードの `member` 以上 | 未ログイン `401`、`viewer` は `403`、閲覧不可 `404` |
| カード配下のラベル一覧取得 (`GET /api/cards/{cardId}/labels`) | 対象ボードの `viewer` 以上 | 未ログイン `401`、閲覧不可 `404` |
| ラベル付与 (`POST /api/cards/{cardId}/labels/{labelId}`) | 対象ボードの `member` 以上、かつラベルとカードが同一ボード | 未ログイン `401`、`viewer` は `403`、閲覧不可 / 別ボード `404` |
| ラベル解除 (`DELETE /api/cards/{cardId}/labels/{labelId}`) | 対象ボードの `member` 以上 | 未ログイン `401`、`viewer` は `403`、閲覧不可 / 別ボード `404` |

## 非機能要件

`spec/000_shared_rules.md § 非機能要件` に従う。本 spec 固有の要件は次の通り。

### 性能

- ラベル作成 / 編集 / 削除 / 付与 / 解除 API は書き込み API として P95 300ms 以内。
- ラベル一覧、カード配下ラベル一覧 API は一覧 API として P95 200ms 以内。

### 運用 (操作ログ)

- ラベル作成、編集、削除、付与、解除の各操作について、操作種別 (`label_create` / `label_update` / `label_delete` / `label_attach` / `label_detach`)、対象識別子 (`labelId`、必要に応じて `cardId`)、対象ボード識別子 (`boardId`)、操作ユーザー識別子 (`userId`)、タイムスタンプを操作ログに残す。
- ラベル削除時にカスケード解除された `CardLabel` 件数もログに記録する。

### セキュリティ

- `constitution.md § セキュリティ` に従う。追加要件なし。

## 未決事項

- ラベルの並び順を手動で変更する機能 (`order` フィールドと並び替え API) は本 spec の対象外。初期実装は `name` 昇順で表示する。
- ラベルを別ボードにコピー / 移動する機能は本 spec の対象外。
- ラベル `color` の追加 / カスタムカラー (HEX 直指定) は本 spec の対象外。
- ラベル `name` の同一ボード内一意性判定の正規化方針 (NFC / 大文字小文字統一) は設計工程で決める。
- ラベルによるカード絞り込みは `spec/008_search_filter.md` で扱う。
- 用語「ラベル (Label)」 の `constitution.md § 用語集` への追加は `/constitution` で判断する。
