# カード詳細の仕様

## 概要

本 file はカード詳細モーダルの拡張仕様を定義する。
`spec/003_cards.md § カード詳細モーダルの基本構造` を土台に、タイトル、説明文、ラベル、期限、担当者、コメントの各表示領域と、カード詳細画面上で完結する担当者割当およびコメント投稿の操作を定義する。
ラベルの CRUD と付与、解除操作は `spec/006_label.md` に、期限の設定、変更、解除、期限切れ表示は `spec/007_due_date.md` に委譲する。
共通ルールは `spec/000_shared_rules.md`、カード基本仕様は `spec/003_cards.md`、ライフサイクル操作は `spec/004_card_movement_archive_restore.md` を参照する。

## 既存仕様との関係

- `spec/003_cards.md § カード詳細モーダルの基本構造` の要素 (`title` / `description` / `createdAt` / `updatedAt` / 削除導線 / 閉じる導線) を SSOT として継承する。
- 本 spec は同モーダルにラベル領域、期限領域、担当者領域、コメント領域を追加する。
- `spec/003_cards.md § 未決事項` の「担当者、期限、コメント欄の配置は本 spec の対象外」 を本 spec で解決する。
- `spec/000_shared_rules.md § 未決事項` の「担当者、コメント機能は別 spec で決める」 を本 spec が担う (期限は `spec/007_due_date.md`、ラベルは `spec/006_label.md`)。

## 対象データ

### Card エンティティへの追加フィールド

`spec/003_cards.md § 対象データ` に、以下のフィールドを追加する。

| フィールド | 型 | 説明 |
|---|---|---|
| `assigneeId` | 文字列 / null | カードに割り当てられたユーザー ID。未割当は `null`。 |

- 担当者はカード 1 枚に対して 0 人または 1 人とする (複数割当は本 spec の対象外)。
- 対象ボードの `viewer` 以上のロールを持つユーザーのみを割当対象とする。
- 割当ユーザーが後日ボードから外れた場合の扱いは `§ 異常系` を参照する。

### Comment エンティティ

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | 文字列 | コメントを一意に識別する ID |
| `cardId` | 文字列 | 所属するカードの ID |
| `authorId` | 文字列 | 投稿者ユーザー ID |
| `body` | 文字列 | コメント本文 (1〜2000 文字) |
| `createdAt` | ISO8601 UTC | 投稿日時 |
| `updatedAt` | ISO8601 UTC | 更新日時 |

- コメントの一意性はカード単位のスコープ外 (`id` はグローバル一意)。
- コメントの並び順は `createdAt` 昇順を第一キーとし、同時刻は `id` 昇順で解決する。
- コメント編集は本 spec の対象外とし、`§ 未決事項` に列挙する (初期実装は投稿と削除のみ)。

## 機能要件

### カード詳細モーダルの拡張構造

カード詳細モーダルには以下の 6 領域を配置する。

| 領域 | 表示内容 | 編集導線 |
|---|---|---|
| タイトル領域 | `title` の表示 | `spec/003_cards.md § 操作: カードタイトル編集` を継承 |
| 説明文領域 | `description` の表示 (0〜2000 文字、空文字許容、plain text) | `spec/003_cards.md § 操作: カード説明文編集` を継承 |
| ラベル領域 | 付与済みラベルのバッジ一覧、およびラベル付与/解除の導線 | `spec/006_label.md` に委譲 |
| 期限領域 | 期限の日付表示、期限切れ表示、および設定/変更/解除の導線 | `spec/007_due_date.md` に委譲 |
| 担当者領域 | 担当者名またはアバターの表示、未割当時のプレースホルダ、および割当/変更/解除の導線 | 本 spec `§ 操作: 担当者の割当` |
| コメント領域 | コメント一覧 (`createdAt` 昇順)、および新規投稿と削除の導線 | 本 spec `§ 操作: コメント投稿` および `§ 操作: コメント削除` |

- モーダル上部にはタイトル領域とメタ情報 (`createdAt` / `updatedAt`) を配置し、下部に説明文、ラベル、期限、担当者、コメントの順で領域を並べる。具体レイアウトは `ui-design/` で決める。
- 各領域は独立して閲覧、編集可能とする (1 領域の編集中に他領域が読み込み中にならない)。
- 領域内での編集 API 呼出が失敗した場合、その領域のみエラー表示に切り替え、他領域は現状を保つ。

### 操作: 担当者の割当

- 担当者領域の「担当者を割り当てる」 導線から実行する。
- 割当候補は「対象ボードの `viewer` 以上のメンバー」 とする。ユーザー選択 UI の詳細は `ui-design/` で決める。
- 割当は 1 名まで。既に担当者が設定されている状態で別ユーザーを選択すると、上書き更新となる。
- 対象カードの `assigneeId` を更新し、`updatedAt` を更新する。

### 操作: 担当者の解除

- 担当者領域の「担当者を解除する」 導線から実行する。
- 対象カードの `assigneeId` を `null` に更新し、`updatedAt` を更新する。

### 操作: コメント投稿

- コメント領域の投稿フォームから実行する。
- 入力項目は `body` のみ (1〜2000 文字、トリム後 0 文字は不可)。
- 投稿後、コメント領域の末尾に追加され、`createdAt` は現在時刻となる。
- 投稿者は現在ログイン中のユーザー (`authorId` はサーバー側で決定)。
- 投稿時、対象カードの `updatedAt` は更新しない (カード本体の変更ではないため)。

### 操作: コメント削除

- コメント一覧の各コメント行から削除導線を実行する。
- 削除は明示的な確認 (確認ダイアログ等) を伴う。UI 詳細は `ui-design/` で決める。
- 削除操作は物理削除 (soft delete しない)。復元は行わない。
- 削除実行可能な条件は次のいずれか。
  - 対象コメントの投稿者本人 (`authorId = 現在ユーザー`) かつ `member` 以上
  - 対象ボードの `owner` (投稿者を問わず削除可能)

## 画面

- カード詳細モーダルは `spec/003_cards.md § カード詳細モーダルの基本構造` を継承する。
- 6 領域の垂直順序、余白、装飾、担当者アバターの表現、コメント入力欄の高さは `ui-design/` で決める。
- 担当者領域は未割当時に「未割当」 相当のプレースホルダを表示する (文言は `ui-design/`)。
- コメント領域は 0 件時に「まだコメントはありません」 相当の空状態を表示する (文言は `ui-design/`)。
- コメント一覧は投稿順で表示し、最新コメントが下部に来る。

## API

| メソッド | パス | 用途 | 必要権限 |
|---|---|---|---|
| `PATCH` | `/api/cards/{cardId}/assignee` | カードの担当者を設定または解除する | 対象ボードの `member` 以上 |
| `GET` | `/api/cards/{cardId}/comments` | 指定カードのコメント一覧を取得 | 対象ボードの `viewer` 以上 |
| `POST` | `/api/cards/{cardId}/comments` | 指定カードにコメントを投稿 | 対象ボードの `member` 以上 |
| `DELETE` | `/api/comments/{commentId}` | コメントを削除 | 投稿者本人 (`member` 以上) または対象ボードの `owner` |

- レスポンス形式と認証チェック順序は `spec/000_shared_rules.md` に従う。
- 一覧 API のレスポンスは `{ items: Comment[] }`、単体 API のレスポンスは `Comment` オブジェクト、担当者更新 API のレスポンスは更新後の `Card` オブジェクト。
- `PATCH /api/cards/{cardId}/assignee` のリクエスト body は `{ "assigneeId": <文字列 | null> }`。`null` を渡すと解除、文字列を渡すと割当。
- `POST /api/cards/{cardId}/comments` のリクエスト body は `{ "body": <文字列> }`。成功時は作成された `Comment` を 201 で返す。
- `DELETE /api/comments/{commentId}` は成功時に 204 (body なし) を返す。

## 受入条件

- [ ] カード詳細モーダルに、タイトル、説明文、ラベル、期限、担当者、コメントの 6 領域が表示される。
- [ ] `member` 以上のユーザーが担当者領域から `viewer` 以上のメンバーを選択すると、`assigneeId` が更新され、モーダル上に担当者名またはアバターが表示される。
- [ ] `member` 以上のユーザーが担当者領域から解除を実行すると、`assigneeId` が `null` になり、モーダル上に未割当プレースホルダが表示される。
- [ ] `member` 以上のユーザーがコメント本文 1〜2000 文字を投稿すると、コメント領域の末尾に投稿内容と投稿者と `createdAt` が表示される。
- [ ] 投稿者本人が自分のコメントに対して削除を実行し確認すると、コメント一覧から消える。
- [ ] `owner` は他ユーザーが投稿したコメントも削除できる。
- [ ] `member` が他ユーザーのコメントを削除しようとすると `403` が返る。
- [ ] `viewer` ロールのユーザーが担当者更新、コメント投稿、コメント削除 API を呼ぶと `403` が返る。
- [ ] 未ログインユーザーが本 spec のいずれの API を呼んでも `401` が返る。
- [ ] 存在しない `cardId` または `commentId` を指定した API 呼出は `404` を返す。
- [ ] 対象ボードの閲覧権限を持たないユーザーが担当者として指定されると `422` (`assignee_not_in_board`) が返る。
- [ ] コメント本文が 0 文字またはトリム後 0 文字の投稿は `422` (`required`) が返る。
- [ ] コメント本文が 2001 文字以上の投稿は `422` (`too_long`) が返る。

## 異常系

`spec/000_shared_rules.md § HTTP ステータスコード` と `§ Route Handler の入口チェック順序` に従う。

### 認証、権限、存在チェック

| 状況 | ステータス | 補足 |
|---|---|---|
| 未ログインで本 spec の API 呼出 | `401` | 全 API 共通 |
| 存在しない `cardId` を指定 | `404` | 担当者更新 / コメント一覧 / コメント投稿 API |
| 存在しない `commentId` を指定 | `404` | コメント削除 API |
| 閲覧権限 (`viewer` 以上) のないボード配下のカード / コメントを指定 | `404` | 存在有無を漏らさないため `404` に統一 |
| `viewer` ロールが担当者更新 / コメント投稿 / コメント削除 API を呼ぶ | `403` | 認証済み、閲覧可の状態が前提 |
| `member` が他ユーザーの投稿コメントを削除しようとする | `403` | 投稿者本人または `owner` のみ削除可 |

### バリデーションエラー / 状態エラー

| 状況 | ステータス | フィールド | メッセージ例 |
|---|---|---|---|
| `assigneeId` が指定ユーザーとして存在しない | `422` | `assigneeId` | `assignee_not_found` |
| `assigneeId` が対象ボードの閲覧権限を持たない | `422` | `assigneeId` | `assignee_not_in_board` |
| `assigneeId` が文字列でも `null` でもない | `422` | `assigneeId` | `invalid_type` |
| `body` 未指定またはトリム後 0 文字 | `422` | `body` | `required` |
| `body` が 2000 文字超過 | `422` | `body` | `too_long` |
| `body` が文字列型でない | `422` | `body` | `invalid_type` |

### 画面レベル

- 担当者選択リスト取得に失敗した場合、担当者領域内に「担当者候補を取得できませんでした。再試行してください」 相当の表示を行う。
- 割当済み担当者が対象ボードから外れた場合、その `assigneeId` は保持したまま、表示は「（無効な担当者）」 相当のプレースホルダに切り替える。再割当は `member` 以上が可能。
- コメント投稿 API が `422` を返した場合、投稿フォーム直下にフィールド別エラーメッセージを表示する (`body: required` / `body: too_long`)。
- コメント削除 API が `403` を返した場合、「操作権限がありません」 相当の表示を行う。
- コメント削除 API が `404` を返した場合 (他ユーザーが同時に削除した等)、対象コメント行を一覧から取り除く。

## 境界条件

### 担当者

- `assigneeId = null` (解除): 受け付ける。
- `assigneeId` = 現在ユーザー自身: 受け付ける (自分にアサイン可能)。
- `assigneeId` = 対象ボードの `viewer`: 受け付ける (viewer も担当者として指名可能)。
- `assigneeId` = 対象ボードに所属しないユーザー: `422` (`assignee_not_in_board`)。
- 既に同じユーザーが担当者に設定されている状態での再割当: `200` で成功、`updatedAt` を更新する。

### コメント本文

- 1 文字 (下限ちょうど): 受け付ける。
- 2000 文字 (上限ちょうど): 受け付ける。
- 2001 文字: `422` を返す。
- 0 文字 (空文字): `422` を返す。
- トリム後 0 文字 (空白のみ): `422` を返す。
- トリム前の先頭、末尾の空白: 保存時にトリムせず原文のまま保存する (本文中の連続空白も保持)。

### コメント一覧

- コメント 0 件: 一覧 API は `{ items: [] }` を 200 で返す。
- 同一 `createdAt` (ミリ秒レベルで一致) のコメント: `id` 昇順で解決する。

### モーダルの領域

- ラベル 0 件: ラベル領域は「ラベルなし」 相当の空状態表示 (詳細は `spec/006_label.md`)。
- 期限未設定: 期限領域は「期限なし」 相当の空状態表示 (詳細は `spec/007_due_date.md`)。
- 担当者未割当: 担当者領域は「未割当」 相当のプレースホルダ表示。

## バリデーション

| フィールド | ルール |
|---|---|
| `assigneeId` (担当者更新 body) | 文字列または `null`。文字列時は存在するユーザーで、かつ対象ボードの閲覧権限を持つこと。それ以外は `422`。 |
| `body` (コメント投稿 body) | 文字列。トリム後 1〜2000 文字。トリム後 0 または 2001 以上で `422`。 |
| `cardId` (URL パラメータ) | 文字列。存在しないと `404`。 |
| `commentId` (URL パラメータ) | 文字列。存在しないと `404`。 |

- コメント投稿 API では `id` / `authorId` / `cardId` / `createdAt` / `updatedAt` はクライアントから受け取らない (サーバー側で決定する)。
- 担当者更新 API で受け付けるのは `assigneeId` のみ。

## 権限境界

`spec/000_shared_rules.md § 権限マトリクス` と本 spec 追加操作を統合した表。

| 操作 | 必要権限 | 権限不足時の挙動 |
|---|---|---|
| 担当者更新 (`PATCH /api/cards/{cardId}/assignee`) | 対象ボードの `member` 以上 | 未ログイン `401`、`viewer` は `403`、閲覧不可 `404` |
| コメント一覧取得 (`GET /api/cards/{cardId}/comments`) | 対象ボードの `viewer` 以上 | 未ログイン `401`、閲覧不可 `404` |
| コメント投稿 (`POST /api/cards/{cardId}/comments`) | 対象ボードの `member` 以上 | 未ログイン `401`、`viewer` は `403`、閲覧不可 `404` |
| コメント削除 (`DELETE /api/comments/{commentId}`) | 投稿者本人 (`member` 以上) または対象ボードの `owner` | 未ログイン `401`、削除権限なし `403`、閲覧不可 `404` |

## 非機能要件

`spec/000_shared_rules.md § 非機能要件` に従う。本 spec 固有の要件は次の通り。

### 性能

- 担当者更新 / コメント投稿 / コメント削除 API は書き込み API として P95 300ms 以内。
- コメント一覧 API は一覧 API として P95 200ms 以内。

### 運用 (操作ログ)

- 担当者更新、コメント投稿、コメント削除の各操作について、操作種別 (`card_assignee_update` / `comment_create` / `comment_delete`)、対象識別子 (`cardId` / `commentId`)、対象ボード識別子 (`boardId`)、操作ユーザー識別子 (`userId`)、タイムスタンプを操作ログに残す。
- 担当者更新時は遷移前 `assigneeId` と遷移後 `assigneeId` を記録する。

### セキュリティ

- `constitution.md § セキュリティ` に従う。追加要件なし。

## 未決事項

- コメント編集機能は本 spec の対象外。将来別 spec で扱う。
- コメントに対する Markdown レンダリング、メンション (`@user`)、リアクション、返信は本 spec の対象外。
- 担当者の複数割当は本 spec の対象外。
- 担当者アバター画像、担当者候補の検索 UI、コメント入力欄のリッチテキスト表現は `ui-design/` で決める。
- 割当済み担当者がボードから外れた場合の自動クリーンアップ (`assigneeId` を null に戻す) は本 spec の対象外 (初期方針は保持したまま表示切替)。
- コメント一覧のページネーションは本 spec の対象外 (初期実装は全件返却)。
- 担当者選択リスト API (`GET /api/boards/{boardId}/members` 等) は本 spec の対象外。既存 API または未定義であるため、初期実装ではクライアントが持つメンバー一覧から選択する前提とし、必要になった時点で別 spec で定義する。
