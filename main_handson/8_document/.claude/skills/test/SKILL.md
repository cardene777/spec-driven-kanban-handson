# /test

仕様からテストケースを導出するスキル。
対象プロジェクトのテストランナー、テスト配置、ヘルパー構成を読み、不足しているテスト軸を補完する。

## トリガー条件

- 「{機能名}のテスト範囲を広げて」、「異常系・境界条件を網羅して」
- TDDサイクルや実装が終わったあと
- リファクタ前に安全網を広げたいとき
- バグ修正後に同じパターンの抜けを確認したいとき

## 入力

- `constitution.md`
- 対象の `spec/*.md`
- 既存テストファイル
- 対象実装ファイル
- テスト実行コマンド

## 出力

既存テストファイルまたは新規テストファイルに、以下4軸の不足分を追加する。

- 正常系
- 異常系
- 境界条件
- 状態遷移

合わせて、必要なテストヘルパーがあれば対象プロジェクトの既存規約に合わせて切り出す。

最後に以下のサマリーを出力する。

```markdown
# /test実行サマリー

対象機能: {機能名}
対象spec: spec/{機能ID}_{機能名}.md
対象テスト: {テストファイルパス}

## 追加件数

| 軸 | 既存 | 追加 | 合計 |
|---|---|---|---|
| 正常系 | {n} | {n} | {n} |
| 異常系 | {n} | {n} | {n} |
| 境界条件 | {n} | {n} | {n} |
| 状態遷移 | {n} | {n} | {n} |

## テスト実行結果

{PASS / FAILの内訳}
```

## 4軸の判定基準

### 正常系

- 受入条件ごとの主経路
- 仕様に書かれた代替経路
- 権限や入力パターンが分かれる場合は、その分岐

### 異常系

- 入力エラー
- 権限エラー
- 整合性エラー
- 対象リソースが存在しないケース

### 境界条件

- 最小値、最大値
- 最大値の内側と外側
- 空、null、未指定
- 仕様に書かれた上限・下限

### 状態遷移

- 遷移前、操作、遷移後の観測
- 主要な作成・更新・削除・復元などの状態変化

## 注意事項

- テストランナーや記法をスキル内で固定しない
- 既存テストを上書きしない
- 仕様と実装が食い違う場合は、どちらを直すかユーザーに確認する
