# /implement

仕様と設計をコードに落とすスキル。
`constitution.md` の技術スタック、規約、権限ポリシー、非機能要件を読み、対象プロジェクトの既存構成に合わせて実装する。

## トリガー条件

- 「この設計を実装して」、「この仕様と設計を実装して」
- `spec/*.md` と `design/*.md` が揃ったあと

## 入力

- `constitution.md`
- 対象の `spec/*.md`
- 対応する `design/*.md`
- 既存コード
- 既存のテスト・ビルド・lintコマンド

## 出力

仕様と設計に従って、必要なファイルを生成または更新する。

- データモデルまたは永続化層
- APIやサーバー側処理
- UIまたは画面側処理
- 認証・認可・ログなどの共通処理
- 対応するテスト

各ファイルには、必要に応じて対応する仕様要件IDと設計セクション参照を残す。

## 作業手順

1. 入力ファイル確認
   `constitution.md`、対象 `spec/*.md`、対象 `design/*.md` を読み込む。
2. 既存コード確認
   既存コード、ディレクトリ構成、実行コマンドを確認する。
3. 実装対象の整理
   仕様と設計から、作成・更新するファイルを列挙する。
4. 共通処理の確認
   認証、認可、ログ、エラー処理、バリデーションなどの共通処理が必要か確認する。
5. コード生成
   対象プロジェクトの技術スタックに合わせて実装する。
6. テスト生成
   正常系、異常系、権限境界、境界条件のうち、仕様で求められるテストを生成する。
7. 静的検証
   `constitution.md` または既存プロジェクトで定義された検証コマンドを実行する。
8. 失敗時対応
   失敗したら修正して再実行する。繰り返し失敗する場合はユーザーに報告する。

## コード生成の方針

- フレームワークやORMをスキル内で固定しない
- 認証・認可ヘルパーの名前をスキル内で固定しない
- 既存のプロジェクト構成を優先する
- 仕様にない機能をついでに追加しない
- エラー処理は `constitution.md` と設計に従う

## 注意事項

- 仕様にない権限チェックを勝手に追加しない。仕様変更が必要なら `/spec` に戻る
- 機密情報や個人情報をログに直接含めない
- テストコマンドやlintコマンドは対象プロジェクトの設定から判断する
