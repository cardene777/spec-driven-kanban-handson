# /review

仕様・設計とコードを機械的に突合するスキル。
`constitution.md`、仕様、設計、実装を読み、5観点でずれを検出する。

## トリガー条件

- 「{機能名}のコードと仕様を突合して」、「仕様準拠か確認して」
- 実装が完了した直後
- 仕様変更があったあと
- 大規模リファクタの直後
- PRマージ前の最終確認

## 入力

- `constitution.md`
- 対象の `spec/*.md`
- 対象の `design/*.md`
- 対象実装ファイル一式
- 既存のレビューレポート

## 出力

`review/{機能ID}_{機能名}_review.md` を生成する。

```markdown
# {機能名} レビューレポート

レビュー日時: {日時}
対象実装: {ファイルパス群}
対象仕様: spec/{機能ID}_{機能名}.md
対象設計: design/{機能ID}_{機能名}.md

## サマリー

| 観点 | 不一致件数 |
|---|---|
| 仕様カバレッジ | {n} |
| 実装カバレッジ | {n} |
| 振る舞いの整合 | {n} |
| 権限境界の整合 | {n} |
| 用語の整合 | {n} |

## 判定

- 合計0件: マージ可能
- 合計1件以上: 修正必要
```

## 5観点の判定基準

### 観点1: 仕様カバレッジ

仕様にあるがコードに無い機能を検出する。

### 観点2: 実装カバレッジ

コードにあるが仕様に無い処理を検出する。

### 観点3: 振る舞いの整合

仕様の入出力、ステータス、レスポンス、表示、状態変化と実装のずれを検出する。

### 観点4: 権限境界の整合

`constitution.md` と仕様に書かれた権限境界が実装されているか確認する。

### 観点5: 用語の整合

`constitution.md` の用語集と、仕様・設計・コード命名のずれを確認する。

## 作業手順

1. 入力ファイル確認
   `constitution.md` と対象仕様・設計を読み込む。
2. 実装ファイル確認
   対象実装ファイルを読み込む。
3. 前回レビュー確認
   既存レビューレポートがあれば確認する。
4. 不一致列挙
   5観点で不一致を列挙する。
5. レポート生成
   レビューレポートを生成する。
6. 修正方針確認
   修正が必要な場合、ユーザーに方針を確認する。

## 注意事項

- ロール名、用語、権限チェック関数名をスキル内で固定しない
- 仕様と実装のどちらを直すべきか判断できない場合はユーザーに確認する
- 自動修正前に、修正対象と理由を提示する
