# /tdd

Red-Green-Refactorのサイクルを進めるスキル。
`constitution.md`、仕様、設計、既存テスト構成を読み、対象プロジェクトのテストランナーと規約に合わせて受入条件を1件ずつ実装する。

## トリガー条件

- 「{機能名}をTDDで実装して」、「Red-Green-Refactorで進めて」
- 設計が固まったあと、実装に入る前
- バグ修正で再現テストから始めたいとき

## 入力

- `constitution.md`
- 対象の `spec/*.md`
- 対象の `design/*.md`
- UI設計文書（必要な場合）
- 既存テストファイルとテスト実行コマンド

## 出力

各ACごとに以下を出力する。

| ファイル | 内容 | フェーズ |
|---|---|---|
| {テストファイル} | 失敗テスト | Red |
| {実装ファイル} | 最小実装 | Green |
| {更新ファイル} | リファクタ後の構造 | Refactor |
| `.context/tdd/cycles.md` | 各サイクルの記録 | 全フェーズ |

最後にTDDサイクルレポートを出力する。

## テスト実行コマンド

テスト実行コマンドは、以下の優先順で決める。

1. `constitution.md` に明記されたコマンド
2. 既存の `package.json`、設定ファイル、CI定義にあるコマンド
3. 既存テストの実行方法
4. 不明な場合はユーザー確認

## 作業手順

### 全AC共通の準備

1. 入力ファイル確認
   `constitution.md` と対象仕様・設計を読み込む。
2. AC抽出
   受入条件を一覧で抽出し、実装順序を確認する。
3. サイクル記録開始
   `.context/tdd/cycles.md` を作成し、サイクル記録を開始する。

### Redフェーズ

1. テストファイル決定
   既存命名規則を参照し、対象ACのテストファイルパスを決める。
2. テストコード作成
   1 ACにつき1つのサイクルで失敗テストを書く。
3. FAIL確認
   テストを実行してFAILを確認する。

### Greenフェーズ

1. 最小実装
   対象ACを通す最小限の実装を書く。
2. PASS確認
   テストを実行してPASSを確認する。
3. 既存テスト確認
   関連する既存テストも実行する。

### Refactorフェーズ

1. 改善項目洗い出し
   重複・命名・責務を確認する。
2. 小さな変更
   振る舞いを変えずに構造を整える。
3. PASS維持確認
   テストがPASSのまま保たれることを確認する。

## 注意事項

- 複数ACを1サイクルに混ぜない
- Greenフェーズで仕様外の実装を盛らない
- テストランナー、ファイルパス、テストスタイルをスキル内で固定しない
