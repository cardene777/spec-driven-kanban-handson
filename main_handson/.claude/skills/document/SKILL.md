# /document

仕様・設計・実装・テストからドキュメントを生成するスキル。
対象プロジェクトの構成と `constitution.md` の用語・権限・運用方針を参照して、必要なドキュメントを生成する。

## トリガー条件

- 「{機能名}のドキュメントを生成して」、「API仕様書を書いて」、「runbookを更新して」
- 実装とレビューが完了したあと
- 仕様変更があったあとのドキュメント追従
- CIやリリース前のドキュメント確認

## 引数

- `--type` 省略時は、api・help・runbook の3種すべてを1回で生成する（既定）
- `--type api` APIリファレンスのみ生成
- `--type help` ユーザーヘルプのみ生成
- `--type runbook` 運用runbookのみ生成
- `--type all` `--type` 省略時と同じ（3種すべて生成）
- `--all` 対象機能を指定せず、`spec/` 配下の全機能を対象に生成する（機能を絞りたい場合は機能IDを指定する）

## 入力

- `constitution.md`
- 対象の `spec/*.md`
- 対象の `design/*.md`
- 対象実装ファイル一式
- 対象テストファイル一式
- CI、環境変数、運用設定（runbook生成時に存在する場合）

## 出力

引数 `--type` に応じて、対象プロジェクトのドキュメント配置に生成する。
配置先が未定義の場合は、以下を標準候補として提示する。

| 種類 | 出力先候補 | 想定対象 |
|---|---|---|
| API | `docs/api/{機能ID}_{機能名}.md` | 開発者 |
| help | `docs/help/{機能ID}_{機能名}.md` | 利用者・サポート担当 |
| runbook | `docs/runbook/{機能ID}_{機能名}.md` | 運用担当 |

## APIリファレンスの構成

- 概要
- エンドポイントまたは公開インターフェース
- 入力
- 出力
- エラー
- 権限
- 関連仕様・関連テスト

## ユーザーヘルプの構成

- 主要操作
- 操作手順
- エラーメッセージと対処法
- よくある質問

## 運用runbookの構成

- 障害シナリオ
- 確認手順
- 復旧手順
- 監視項目
- 関連ファイル

## 作業手順

1. **入力確認**

   仕様、設計、実装、テスト、`constitution.md` を読み込む。
2. **出力種別確認**

   `--type` の指定があればその種別のみ、省略時（または `--type all`）は api・help・runbook の3種すべてを生成する。3種を生成する場合は、種類ごとに入力（API はテスト、help は画面、runbook は運用設定）を読み分ける。
3. **用語変換**

   `constitution.md` の用語集に合わせて表記を揃える。
4. **ドキュメント生成**

   想定対象に合わせた粒度で生成する。
5. **差分確認**

   既存ドキュメントがある場合は上書き前に差分を確認する。
6. **ファイル書き出し**

   ユーザー承認後に書き出す。

## 注意事項

- 技術用語は想定対象に合わせて言い換える
- APIパス、環境変数、CI配置をスキル内で固定しない
- 実装と異なる内容を書かない。矛盾があれば先に報告する
