# /document

仕様・設計・実装・テストからドキュメントを生成するスキル。
対象プロジェクトの構成と `constitution.md` の用語・権限・運用方針を参照して、必要なドキュメントを生成する。

## トリガー条件

- 「{機能名}のドキュメントを生成して」、「API仕様書を書いて」、「運用手順書（runbook）を更新して」
- 実装とレビューが完了したあと
- 仕様変更があったあとのドキュメント追従
- CIやリリース前のドキュメント確認

## 引数

- `--type api` APIリファレンスのみ生成
- `--type help` ユーザーヘルプのみ生成
- `--type runbook` 運用手順書のみ生成
- `--type all` すべて生成（省略時は標準）
- `--all` 対象機能を指定せず、変更検知された全機能を生成

## 入力

- `constitution.md`
- 対象の `spec/*.md`
- 対象の `design/*.md`
- 対象機能に対応する実装ファイル
- 対象機能に対応するテストファイル
- CI、環境変数、運用設定（運用手順書を生成する場合に存在するもの）

## 出力

引数 `--type` に応じて、対象プロジェクトのドキュメント配置に生成する。
配置先が未定義の場合は、以下を標準候補として提示する。

| 種類 | 出力先候補 | 想定対象 |
|---|---|---|
| API | `docs/api/{機能ID}_{機能名}.md` | 開発者 |
| help | `docs/help/{機能ID}_{機能名}.md` | 利用者・サポート担当 |
| 運用手順書 | `docs/runbook/{機能ID}_{機能名}.md` | 運用担当 |

## APIリファレンスの構成

- 概要
- エンドポイントまたは公開インターフェース
- 入力
- 出力
- エラー
- 権限
- 関連仕様・関連テスト

## ユーザーヘルプの構成

- 主要操作
- 操作手順
- エラーメッセージと対処法
- よくある質問

## 運用手順書の構成

- 障害シナリオ
- 確認手順
- 復旧手順
- 監視項目
- 関連ファイル

## 作業手順

1. 入力確認
   仕様、設計、実装、テスト、`constitution.md` を読み込む。
2. 出力種別確認
   `--type` に応じて生成対象を決める。
3. 用語変換
   `constitution.md` の用語集に合わせて表記を揃える。
4. ドキュメント生成
   想定対象に合わせた粒度で生成する。
5. 差分確認
   既存ドキュメントがある場合は上書き前に差分を確認する。
6. ファイル書き出し
   ユーザー承認後に書き出す。

## 注意事項

- 技術用語は想定対象に合わせて言い換える
- APIパス、環境変数、CI配置をスキル内で固定しない
- 実装と異なる内容を書かない。矛盾があれば先に報告する
