# /spec-review

仕様の品質を機械的にチェックするスキル。
`constitution.md` と関連仕様を参照し、曖昧表現・抜け漏れ・矛盾・テスト不能項目を4つの観点でレビューする。

## トリガー条件

- 「この仕様をレビューして」、「{機能名}の仕様の曖昧さを検出して」
- `spec/*.md` を出力した直後
- 実装に入る前の最終確認

## 入力

- `constitution.md`（用語集・権限ポリシー参照用）
- レビュー対象の `spec/*.md`
- 関連する既存 `spec/*.md`（横断整合チェック用）

## 出力

`review/{機能ID}_{機能名}_review.md` を生成する。

```markdown
# {機能名} 仕様レビュー

レビュー日時: {日時}
対象ファイル: spec/{機能ID}_{機能名}.md

## サマリー

| 観点 | 検出件数 |
|---|---|
| 曖昧表現 | {n} |
| 抜け漏れ | {n} |
| 矛盾 | {n} |
| テスト不能項目 | {n} |
| 合計 | {n} |

## 観点1: 曖昧表現

## 観点2: 抜け漏れ

## 観点3: 矛盾

## 観点4: テスト不能項目
```

## 4つのレビュー観点

### 観点1: 曖昧表現の検出

- 主観的表現
- 数値で測れない形容
- 不定量表現
- 留保表現

検出したら、`constitution.md` の数値目標または具体的な条件への書き換えを提案する。

### 観点2: 抜け漏れの検出

- 機能要件
- 異常系
- 境界条件
- バリデーション
- 非機能要件
- 権限境界
- 用語参照

足りないセクションがあれば、必要な追記を提案する。

### 観点3: 矛盾の検出

- 仕様内の条件矛盾
- 関連仕様との用語やAPI責務のずれ
- `constitution.md` の権限ポリシーや用語集との不一致

どちらが正しいか判断できない場合は、ユーザー確認を挟む。

### 観点4: テスト不能項目の検出

- 主観的判断が必要な要件
- 観測不能な内部状態への言及
- 環境依存な要件
- 副作用が明示されていない処理

テスト可能な形への書き換えを提案する。

## 作業手順

1. Constitution確認
   `constitution.md` をReadで読み込む。
2. レビュー対象確認
   レビュー対象の `spec/*.md` をReadで読み込む。
3. 関連spec確認
   関連する既存 `spec/` をGlobで探し読み込む。
4. 観点別チェック
   4つの観点で機械的にチェックする。
5. レポート生成
   出力テンプレートに従ってレビューレポートを生成する。
6. 修正方針確認
   ユーザーにレビュー結果を提示し、修正方針を確認する。

## 注意事項

- レビュー結果は元仕様を直接書き換えず、まず別ファイルに出す
- 修正判断が必要な箇所はAIだけで決めない
- スキル内に特定ドメインのロール名や用語を固定しない
