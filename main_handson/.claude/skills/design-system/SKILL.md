# /design-system

見た目の共通ルールを定義するSkill。
色、書体、余白、角丸、影を `brand.json` とCSS変数に記録し、既存の画面とコンポーネントで同じ値を参照できるようにする。

## 入力

- `constitution.md`
- 既存の `brand.json`、`app/tokens.css`、`app/globals.css`（存在する場合）
- 対象のページとコンポーネント
- ブランド方針。トーン、アクセント色、書体、余白、角丸、影を含める

## 出力

- `brand.json`。ブランド方針の原本
- `app/tokens.css`。`brand.json` の値をCSS変数として定義するファイル
- `app/globals.css`。トークンをTailwind CSSのテーマと基本スタイルへ対応付けるファイル
- 既存のページとコンポーネントのスタイル更新

コンポーネントライブラリや共通レイアウトを導入するかどうかは、既存の技術スタックとユーザー入力で決める。入力にないライブラリ、サイドバー、ヘッダー、ページは追加しない。

## 作業手順

1. **既存構成を確認する**

   `constitution.md`、既存のスタイルファイル、対象コンポーネントを読む。既存のトークンと直接指定された色・余白を確認する。

2. **ブランド方針を確認する**

   トーン、アクセント色、書体、余白、角丸、影に不足があれば確認する。未確認の値は推測しない。

3. **トークンを定義する**

   `brand.json` に値を記録し、`app/tokens.css` に対応する `--brand-*` 変数を定義する。`app/globals.css` からトークンを読み込み、利用するTailwind CSSのテーマへ対応付ける。

4. **既存画面を更新する**

   直接指定された色・余白・角丸をトークン参照へ置き換える。置換できない箇所は対象と理由を報告する。

5. **検証結果を報告する**

   更新したファイル、残した直接指定、実行した検証コマンドと結果を示す。

## 注意事項

- `brand.json` を色や余白の原本とし、同じ値を複数のファイルへ直接書かない
- 既存の構成を上書きする場合は、対象と理由を先に示す
- コンポーネントライブラリの導入、共通レイアウトの追加、画面構成の変更は、入力で明示された場合だけ行う
- 画面の構造と状態の設計は `/ui-design` が担当する
