# Simple Kanban Constitution

## プロジェクト概要

- Simple Kanban は、小規模チームがタスクをボード、リスト、カードで管理する Web アプリである。
- 仕様、設計、実装、テスト、レビュー、ドキュメントを分けて管理し、各工程の成果物を独立したファイルとして残す。
- 本ドキュメント (`constitution.md`) は、以降の全工程が判断基準として参照する共通の土台とする。

## 技術スタック

| 分類 | 採用技術 |
|---|---|
| フレームワーク | Next.js（App Router） |
| 言語 | TypeScript |
| データベース | SQLite |
| ORM | Prisma 7（`@prisma/adapter-better-sqlite3` 経由の adapter 方式） |
| スタイリング | Tailwind CSS |
| テストランナー | Vitest |
| パッケージマネージャ | npm |

## コーディング規約

- API は Next.js の Route Handler で実装する。
- データアクセスは Prisma に集約し、Route Handler から直接 SQL を発行しない。
- HTTP ステータスコードは以下の 5 種類を用途に応じて返す。
  - バリデーション失敗: `422`
  - 未認証: `401`
  - 権限不足: `403`
  - リソース未存在: `404`
  - 予期しないサーバーエラー: `500`
- エラー応答は `{ "error": { "code": "<コード>", "message": "<日本語メッセージ>" } }` の形に統一する。
- テストは仕様の正常系、異常系、境界条件を確認できる単位で配置し、対象仕様の要件 ID をコメントに残す。
- 認証・権限・ロガーなど複数機能で共有する処理は `lib/` に集約し、Route Handler と UI から重複実装しない。

## 基本原則

- 仕様、設計、実装、テスト、レビュー、ドキュメントを分けて管理する。
- 各工程は前工程の成果物を判断基準として参照する。
- `constitution.md` を全工程の共通の基準とし、判断が分かれたときはここに立ち返る。

## 非機能要件

### 性能

- 一覧 API の P95 レスポンスタイムは 200ms 以内を目標とする（ローカル SQLite、少量データ前提）。
- 書き込み API の P95 レスポンスタイムは 300ms 以内を目標とする。
- 数値は本番 SLA ではなく、ローカル開発環境での開発時安全域として扱う。

### 可用性

- ローカル開発環境が対象であり、稼働率（SLA）の数値目標は設けない。

### セキュリティ

- ローカル開発用の SQLite を使用し、機密データは扱わない。
- 認証は将来的にセッション Cookie ベースで導入する前提で、本章の初期実装では認証済みユーザーを固定的に扱ってよい（`spec/000_shared_rules.md` で明示する）。

### 運用

- 操作ログとエラーログは、あとから追跡できる形で残す。
- リクエスト ID を発行し、エラーログと操作ログの両方に付与する。

## 権限ポリシー

### ロール

| ロール | 説明 | デフォルト権限 |
|---|---|---|
| `owner` | ボードの所有者。 | ボードの作成、編集、削除、メンバー招待、権限変更 |
| `member` | ボードに招待された作業者。 | リストとカードの作成、編集、移動、コメント投稿 |
| `viewer` | ボードに招待された閲覧者。 | 閲覧のみ |

### 操作と必要権限

| 操作 | 必要権限 |
|---|---|
| ボード作成 | `owner`（作成後、作成者は自動で `owner`） |
| ボード編集 | `owner` |
| ボード削除 | `owner` |
| メンバー招待 | `owner` |
| 権限変更 | `owner` |
| リスト作成、編集、削除、移動 | `member` 以上 |
| カード作成、編集、削除、移動 | `member` 以上 |
| コメント投稿 | `member` 以上 |
| ボード、リスト、カード、コメントの閲覧 | `viewer` 以上 |

### 権限チェックの実装方針

- 認証チェックと権限チェックは Route Handler の入口で実施する（順序: 認証 → 対象存在 → 権限 → 入力検証）。
- 未ログインは `401` を返す。
- ログイン済みだが権限が不足している場合は `403` を返す。
- 対象リソースが存在しない場合は `404` を返す（存在確認は権限チェックの前でも後でもよいが、応答は「存在しない場合は 404 を優先する」）。
- 入力バリデーションが失敗した場合は `422` を返す。

## 用語集

| 用語 | 英訳 | 定義 |
|---|---|---|
| ボード | Board | カンバンの最上位単位。 |
| リスト | List | ボード内の列。 |
| カード | Card | タスクを表す項目。 |
| 担当者 | Assignee | カードに割り当てられたユーザー。 |
| 期限 | Due Date | カードの完了予定日。 |
| コメント | Comment | カードに残す会話。 |
| アーカイブ | Archive | 表示対象から外す操作。 |
| 復元 | Restore | アーカイブや削除状態から戻す操作。 |
| ラベル | Label | カードに付与する分類タグ。 |
