# Simple Kanban Constitution

## プロジェクト概要

Simple Kanban は、小規模チームがタスクをボード・リスト・カードで管理する Web アプリケーションである。
仕様・設計・実装・テスト・レビュー・ドキュメントを工程ごとに分けて管理し、各工程の成果物を後続工程の判断基準とする。

## 技術スタック

| 分類 | 採用技術 |
|---|---|
| フレームワーク | Next.js |
| 言語 | TypeScript |
| データベース | SQLite |
| ORM | Prisma |
| スタイリング | Tailwind CSS |
| テスト | Vitest |
| パッケージマネージャ | npm |

## コーディング規約

- API は Next.js の Route Handler で実装する。
- データアクセスは Prisma に集約する。
- HTTP ステータスコードは次の方針で返す。
  - バリデーション失敗: 422
  - 未認証（未ログイン）: 401
  - 権限不足: 403
  - 存在しないリソース: 404
- テストは、仕様の正常系・異常系・境界条件を確認できる単位で置く。

## 基本原則

- 仕様・設計・実装・テスト・レビュー・ドキュメントを分けて管理する。
- 各工程は前工程の成果物を判断基準として参照する。
- constitution.md を全工程の共通の基準とする。

## 非機能要件

### 性能

- 一覧 API の P95 レスポンスタイムは 200ms 以内を目標とする。
- 書き込み API の P95 レスポンスタイムは 300ms 以内を目標とする。

### 可用性

- ローカル開発環境が対象であり、稼働率（SLA）の数値目標は設けない。

### セキュリティ

- ローカル開発用の SQLite を使い、機密データは扱わない。

### 運用

- 操作ログとエラーログは、あとから追跡できる形で残す。

## 権限ポリシー

### ロール

| ロール | 説明 | デフォルト権限 |
|---|---|---|
| owner | ボードの所有者。ボード管理とメンバー管理を行う | ボードの作成・編集・削除、メンバー招待、権限変更 |
| member | ボードの参加者。コンテンツを編集する | リスト・カードの作成・編集・移動、コメント投稿 |
| viewer | ボードの閲覧者 | 閲覧のみ |

### 操作と必要権限

| 操作 | 必要権限 |
|---|---|
| ボードの作成 | owner |
| ボードの編集 | owner |
| ボードの削除 | owner |
| メンバー招待 | owner |
| 権限変更 | owner |
| リストの作成・編集・移動 | member |
| カードの作成・編集・移動 | member |
| コメント投稿 | member |
| ボード・リスト・カードの閲覧 | viewer |

### 権限チェックの実装方針

- 未ログインのリクエストは 401 を返す。
- ログイン済みだが必要権限を満たさないリクエストは 403 を返す。
- 上位ロールは下位ロールの操作を包含する（owner は member・viewer の操作を、member は viewer の操作を行える）。

## 用語集

| 用語 | 英訳 | 定義 |
|---|---|---|
| ボード | Board | カンバンの最上位単位 |
| リスト | List | ボード内の列 |
| カード | Card | タスクを表す項目 |
| 担当者 | Assignee | カードに割り当てられたユーザー |
| 期限 | Due Date | カードの完了予定日 |
| コメント | Comment | カードに残す会話 |
| アーカイブ | Archive | 表示対象から外す操作 |
| 復元 | Restore | アーカイブや削除状態から戻す操作 |
