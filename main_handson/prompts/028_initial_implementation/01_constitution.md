/constitution

新しいカンバンアプリのconstitution.mdを作成してください。

プロジェクト概要

- 名前はSimple Kanbanです。
- 小規模チームがタスクをボード、リスト、カードで管理するWebアプリです。
- 仕様、設計、実装、テスト、レビュー、ドキュメントを分けて管理します。

技術スタック

- Next.js 16（App Router、create-next-app は --webpack で初期化）
- TypeScript
- SQLite
- Prisma（SQLiteを接続先にする）
- Tailwind CSS
- Vitest 4
- npm
- lint は eslint を直接使う（next lint は使わない）
- Node.js 20.19 以上

コーディング規約

- APIはNext.jsのRoute Handlerで実装します。
- データアクセスはPrismaに集約します。
- バリデーション失敗は422、未認証は401、権限不足は403、存在しないリソースは404、予期しないサーバー側エラーは500を返します。
- エラー応答は `{ "error": "<エラー名>" }` を基本とします。入力値の項目別エラーは `{ "error": "validation_error", "fields": { "<フィールド名>": "<理由>" } }` の形に統一します。
- テストは仕様の正常系、異常系、境界条件を確認できる単位で置きます。
- 認証、権限、ログなど複数機能で共有する処理は `lib/` に集約します。

非機能要件

- 一覧APIの応答時間は200ms以内、書き込みAPIの応答時間は300ms以内を、ローカルSQLite・少量データを前提にした設計目標として書きます。CHAPTER 05では測定も達成判定も行いません。
- 稼働率の数値目標は設けません（ローカル開発環境が対象のため）。
- ローカル開発用のSQLiteを使い、機密データは扱いません。
- 操作ログとエラーログは、あとから追跡できる形で残します。リクエストIDを発行して両方に付与します。

権限ポリシー

- ロールはowner、member、viewerの3つです。
- ownerはボードの作成、編集、削除、メンバー招待、権限変更ができます。
- memberはリストとカードの作成、編集、移動、削除、コメント投稿ができます。
- viewerは閲覧のみできます。
- 未ログインは401、権限不足は403を返します。閲覧権限のないリソースは存在有無を漏らさないため404を返します。
- API処理では「認証 → 対象存在 → 権限 → 入力検証」の順で判定します。
- 最初のBoard・List・Cardの実装では認証と権限確認を実装せず、基本APIは権限確認を通過する前提にします。`User`、`BoardMembership`、3ロールの確認、資格情報の検証、セッション管理、ログイン、招待、権限管理の画面、利用者の切り替えはCHAPTER 05では実装しません。操作ログは初期実装に含めます。

用語集

- ボードはカンバンアプリの最上位単位です。英訳はBoardです。
- リストはボード内の列です。英訳はListです。
- カードはタスクを表す項目です。英訳はCardです。
- 担当者はカードに割り当てられたユーザーです。英訳はAssigneeです。
- 期限はカードの完了予定日です。英訳はDue Dateです。
- コメントはカードに残す会話です。英訳はCommentです。
- アーカイブは表示対象から外す操作です。英訳はArchiveです。
- 復元はアーカイブや削除状態から戻す操作です。英訳はRestoreです。
- ラベルはカードに付与する分類タグです。英訳はLabelです。
