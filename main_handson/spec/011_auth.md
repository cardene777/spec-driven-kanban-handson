# 認証の仕様

## 概要

サインアップ・ログイン・ログアウト・セッション確認を定義する。未認証のリクエストは 401 を返す。パスワードはハッシュ化して保存し、認証失敗時に具体的な失敗理由を返さない。

## 既存仕様との関係

- 共通規約（エラー形式・ステータス・ログ方針）は `spec/000_shared_rules.md` を参照する。
- 本仕様で **User / Session** を確定する。既存仕様（001-009）が「後続機能で確定」としていた認証の実体はここで定義する。
- ボードごとの権限（owner/member/viewer）は `spec/013_permissions.md`、招待は `spec/012_member_invite.md`。

## 対象データ

- User
  - `id`: string（サーバー採番）
  - `email`: string（メールアドレス形式・全体で一意）
  - `passwordHash`: string（ハッシュ化済み。平文は保存しない）
  - `name`: string（1〜50文字）
  - `createdAt`: datetime
  - `updatedAt`: datetime
- Session
  - `id`: string（サーバー採番）
  - `userId`: string（対象ユーザー）
  - `token`: string（**暗号論的乱数（CSPRNG）で 32 バイト以上を生成し、URL-safe な文字列にエンコードした値**・一意）
  - `expiresAt`: datetime（発行から 7 日後）
  - `createdAt`: datetime
- セッションの有効判定は `now < expiresAt` とする（`now >= expiresAt` は期限切れ）。
- トークン強度は教材用の簡略仕様であり、実運用の認証方針を示すものではない。

## 機能要件

### 操作: サインアップ（FR-001）

- `email` / `password` / `name` を受け取り User を作成する。
- `password` はハッシュ化して `passwordHash` に保存する（平文保存・平文ログ出力をしない）。
- 作成後、セッションを発行してログイン状態にする。
- 完了条件: User が 1 件作成され、セッション Cookie が発行され、`GET /api/auth/session` が当該ユーザーを返す。

### 操作: ログイン（FR-002）

- `email` / `password` を受け取り、`passwordHash` と照合する。
- 一致した場合のみセッションを発行する。
- 完了条件: 認証成功でセッション Cookie が発行され、`GET /api/auth/session` が当該ユーザーを返す。

### 操作: ログアウト（FR-003）

- 現在のセッションを破棄し、セッション Cookie を無効化する。
- **破棄するのは現在のセッションのみ**とし、同一ユーザーの他デバイス／他セッションは有効のまま残す。
- 完了条件: 実行後 `GET /api/auth/session` が未認証（401）を返し、同一ユーザーの別セッションでは 200 を返す。

### 操作: セッション確認（FR-004）

- 現在のセッションから認証中のユーザーを `{ "user": { "id": ..., "email": ..., "name": ... } }` の形状で返す。
- 完了条件: 有効なセッションがあれば 200 で上記形状を返し、無ければ 401 を返す。

### 操作: 未認証リクエストの拒否（FR-005）

- 認証を要する API に有効なセッションなしでアクセスした場合、401 / UNAUTHORIZED を返す。
- 完了条件: セッションなしの保護 API 呼び出しが 401 を返す。

## 画面

- `/signup`（サインアップ画面）
  - 入力: `name` / `email` / `password`。送信でアカウント作成 → ログイン状態にしてボード一覧へ遷移。
  - エラー表示: 入力不備（422）、既に登録済みの email（409）。
- `/login`（ログイン画面）
  - 入力: `email` / `password`。送信でログイン → ボード一覧へ遷移。
  - エラー表示: 認証失敗時は「メールアドレスまたはパスワードが正しくありません」の共通メッセージのみ（どちらが誤りかを示さない）。
- ログアウト操作: アプリ共通ヘッダー/サイドバーのユーザーメニューから実行し、`/login` へ遷移する。
- 画面状態: 未入力 / 送信中 / エラー表示 / 成功遷移。
- 認証画面は共通レイアウト（AppShell）を使わず、全画面中央のカードパネルで表示する。

## API

| メソッド | パス | 用途 | 必要権限 |
|---|---|---|---|
| POST | /api/auth/signup | サインアップ（User 作成＋セッション発行） | 不要（未認証で実行） |
| POST | /api/auth/login | ログイン（セッション発行） | 不要（未認証で実行） |
| POST | /api/auth/logout | ログアウト（セッション破棄） | 認証済み |
| GET | /api/auth/session | セッション確認（現在のユーザー取得） | 認証済み |

- セッションは Cookie で受け渡す。Cookie 名は `session`、属性は **`HttpOnly` / `SameSite=Lax` / `Path=/`** を必ず付与し、HTTPS 環境（本番）では **`Secure`** も付与する。
- ログアウトでは同名 Cookie を `Max-Age=0` で失効させる。
- `GET /api/auth/session` の成功レスポンスは `{ "user": { "id": ..., "email": ..., "name": ... } }` 形状。

## 受入条件

- [ ] POST /api/auth/signup に有効な `email` / `password` / `name` を渡すと 201 でユーザーが作成され、セッション Cookie が発行される
- [ ] サインアップ後に GET /api/auth/session を呼ぶと 200 で `{ "user": { "id", "email", "name" } }` 形状を返す
- [ ] サインアップのレスポンスに `passwordHash`（およびパスワード平文）が含まれない
- [ ] サインアップ／ログインの Set-Cookie に `HttpOnly` と `SameSite=Lax` と `Path=/` が含まれる
- [ ] 発行されたセッション `token` の長さが 32 文字以上である
- [ ] 連続して 2 回セッションを発行すると、それぞれの `token` が一致しない
- [ ] 既に登録済みの `email` でサインアップすると 409 / CONFLICT を返す
- [ ] `email` がメールアドレス形式でないとき 422 / VALIDATION_ERROR を返す
- [ ] `password` が 7 文字のとき 422 / VALIDATION_ERROR を返す
- [ ] `password` が英字のみ（数字なし）のとき 422 / VALIDATION_ERROR を返す
- [ ] `password` が数字のみ（英字なし）のとき 422 / VALIDATION_ERROR を返す
- [ ] `password` が記号を含まないとき 422 / VALIDATION_ERROR を返す
- [ ] `name` が空文字のとき 422 / VALIDATION_ERROR を返す
- [ ] POST /api/auth/login に正しい `email` / `password` を渡すと 200 でセッション Cookie が発行される
- [ ] 存在しない `email` でログインすると 401 / UNAUTHORIZED を返す
- [ ] 誤った `password` でログインすると 401 / UNAUTHORIZED を返す
- [ ] email 不存在とパスワード不一致のログイン失敗レスポンスが、ステータス（401）・`error.code`（UNAUTHORIZED）・`error.message` のすべてにおいて同一である
- [ ] POST /api/auth/logout は 200 を返し、以降の GET /api/auth/session が 401 を返す
- [ ] ログアウト後も、同一ユーザーの別セッションでは GET /api/auth/session が 200 を返す
- [ ] ログアウトのレスポンスがセッション Cookie を失効させる（`Max-Age=0`）
- [ ] セッションなしで GET /api/auth/session を呼ぶと 401 / UNAUTHORIZED を返す
- [ ] 有効期限を過ぎたセッションで GET /api/auth/session を呼ぶと 401 / UNAUTHORIZED を返す
- [ ] DB に保存された `passwordHash` が入力した平文パスワードと一致しない（ハッシュ化されている）
- [ ] 同一のパスワードで 2 つのアカウントを作成したとき、それぞれの `passwordHash` が異なる（ソルトが付与されている）
- [ ] `email` が `a@b`（トップレベルドメインなし）のとき 422 / VALIDATION_ERROR を返す
- [ ] `email` が `a@b.co` のときサインアップに成功する

## 異常系

- `email` の形式不正、`password` の長さ・文字種違反、`name` の長さ違反は 422 / VALIDATION_ERROR。
- `email` の重複（既に登録済み）は 409 / CONFLICT。
- ログイン失敗（email 不存在・パスワード不一致）は 401 / UNAUTHORIZED。**どちらが原因かを示さない共通メッセージ**を返す。
- セッションなし・セッション期限切れ・不正トークンでの保護 API 呼び出しは 401 / UNAUTHORIZED。
- 予期しないサーバー側エラーは 500 / INTERNAL_ERROR。

## 境界条件

- `password` 7 文字: 422（下限外側）。
- `password` 8 文字（英字・数字・記号を各1以上含む）: 許可（下限内側）。
- `password` 200 文字: 許可（上限内側）。
- `password` 201 文字: 422（上限外側）。
- `name` 0 文字: 422。1 文字: 許可。50 文字: 許可。51 文字: 422。
- セッション有効期限ちょうど（`expiresAt` と同時刻）: 期限切れとして扱い 401。
- セッション有効期限の 1 秒前: 有効（200）。

## バリデーション

- `email`: 必須。メールアドレス形式は **`^[^\s@]+@[^\s@]+\.[^\s@]+$` を満たすこと**（教材用の簡易判定。`a@b` は不可、`a@b.co` は可）。形式不正は 422。既存ユーザーと重複する場合は 409。
- `password`: 必須。**8〜200 文字**。英字（a-z / A-Z）、数字（0-9）、記号をそれぞれ 1 文字以上含む。違反は 422。
  - 本条件は教材用の簡略仕様であり、実運用の認証方針を示すものではない。
- `name`: 必須。1〜50 文字（前後の空白は除去して判定）。違反は 422。

## 権限境界

| 操作 | 必要権限 | 異常時の動作 |
|---|---|---|
| サインアップ | 不要（未認証で実行） | 入力不備は 422、email 重複は 409 |
| ログイン | 不要（未認証で実行） | 認証失敗は 401（理由を区別しない） |
| ログアウト | 認証済み | 未認証は 401 |
| セッション確認 | 認証済み | 未認証・期限切れは 401 |

## ログ

- サインアップ成功・ログイン成功・ログイン失敗・ログアウトを操作ログに記録する。リクエスト ID を付与する（`spec/000_shared_rules.md` § ログ方針）。
- 記録する項目: リクエスト ID / 操作種別 / `userId`（判明している場合）/ 結果。
- **パスワード平文・`passwordHash`・セッショントークンをログに出力しない**。
- ログイン失敗ログには email 不存在かパスワード不一致かの内部区別を記録してよいが、API レスポンスには出さない。

## ドキュメント化に必要なユーザー操作

- アカウントを作成する（`/signup`）。
- ログインする（`/login`）。
- ログアウトする（ユーザーメニュー）。
- ログインできないときの確認手順（メールアドレス・パスワードの確認、アカウント未作成の場合はサインアップ）。

## 非機能要件

- 認証系API（書き込み）の応答時間は300ms以内、セッション確認の応答時間は200ms以内（constitution.md § 性能）。
- パスワードは**ソルト付きでハッシュ化**して保存する（平文保存しない。同一パスワードでも保存値が一致しない）。
- 認証失敗時に具体的な失敗理由を返さない（ステータス・`error.code`・`error.message` を同一にする）。
- セッショントークンは CSPRNG で 32 バイト以上を生成する。
- ログイン試行のレート制限・アカウントロックは**本仕様の対象外**（教材用の簡略仕様。実運用では別途必要）。
- 操作ログ・エラーログにリクエスト ID を付与する（`spec/000_shared_rules.md`）。
