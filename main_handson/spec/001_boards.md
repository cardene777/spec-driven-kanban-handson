# ボード機能の仕様

## 概要

ボード (Board) はカンバンの最上位単位である。
本 file は、ボード一覧画面、ボード詳細画面 (レイアウトのみ)、ボードの作成、名称編集、削除の仕様を定義する。
共通ルールは `spec/000_shared_rules.md` を参照する。

## 対象データ

`Board` エンティティのフィールド。

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | 文字列 | ボードを一意に識別する ID |
| `title` | 文字列 | ボード名 (1〜100 文字) |
| `order` | 数値 | ボード一覧内での並び順 (昇順) |
| `createdAt` | ISO8601 UTC | 作成日時 |
| `updatedAt` | ISO8601 UTC | 更新日時 |

## 機能要件

### 画面: ボード一覧 (`/`)

- ログイン中のユーザーが閲覧権限 (`viewer` 以上) を持つ全ボードを、`order` 昇順、`createdAt` 昇順の順で一覧表示する。
- 各ボード行は `title` を表示し、クリックで `/boards/[id]` に遷移する。
- 画面上にボード新規作成の導線を配置する (詳細な UI は `ui-design/` で決定)。
- ボードが 1 件も存在しない場合、共通ルールに従い空状態を表示する。

### 画面: ボード詳細 (`/boards/[id]`)

- 指定 ID のボードが存在し、かつ閲覧権限 (`viewer` 以上) がある場合、そのボードの `title` を画面上部に表示する。
- ボード内のリスト一覧を画面本体に表示する (リスト表示の詳細は `spec/002_lists.md`)。
- 各リスト内のカード一覧を表示する (カード表示の詳細は `spec/003_cards.md`)。
- 対象ボードが存在しない場合、または閲覧権限がない場合の挙動は `§ 異常系` に従う。

### 操作: ボード作成

- ボード一覧画面から新規作成する。
- 入力項目は `title` のみ。
- 作成後、新規ボードは既存ボード群の末尾に配置される (`order` は同一スコープの末尾)。

### 操作: ボード名編集

- ボード詳細画面からタイトルを編集する。
- 変更対象は `title` のみ。

### 操作: ボード削除

- ボード詳細画面から実行する。
- 削除操作は明示的な確認 (確認ダイアログ等) を伴う。UI 詳細は `ui-design/` で決定する。
- 削除時、`spec/000_shared_rules.md § カスケード削除` に従い、配下のリストとカードを全て削除する。

## API

| メソッド | パス | 用途 | 必要権限 |
|---|---|---|---|
| `GET` | `/api/boards` | 閲覧可能なボード一覧を取得 | `viewer` 以上 |
| `GET` | `/api/boards/{boardId}` | 指定ボードの詳細を取得 | `viewer` 以上 |
| `POST` | `/api/boards` | ボードを新規作成 | ログイン済みユーザー（作成者が owner となる） |
| `PATCH` | `/api/boards/{boardId}` | ボード名を更新 | `owner` |
| `DELETE` | `/api/boards/{boardId}` | ボードを削除 | `owner` |

- レスポンス形式、一覧の並び順、認証チェック順序は `spec/000_shared_rules.md` に従う。
- 一覧 API のレスポンスは `{ items: Board[] }`、単体 API のレスポンスは `Board` オブジェクト。

## 受入条件

- [ ] ログイン済みユーザーが `/` を開くと、閲覧可能なボードが `order` 昇順で表示される。
- [ ] ボードが 0 件のとき、`/` に空状態が表示される。
- [ ] ボード一覧の新規作成導線からタイトル 1〜100 文字を入力してボードを作成すると、末尾に追加される。
- [ ] 作成したボードをクリックすると `/boards/[id]` に遷移し、タイトルが画面上部に表示される。
- [ ] ボード詳細画面でタイトルを編集して保存すると、一覧と詳細の両方で新タイトルが反映される。
- [ ] ボード詳細画面から削除を実行し確認すると、そのボードは一覧から消え、`/boards/[id]` は 404 相当の表示になる。
- [ ] ボード削除時、そのボードに紐づく全リストと全カードが削除されている。
- [ ] ボード編集、削除 API を `owner` ではないユーザーが呼ぶと `403` が返る。
- [ ] 未ログインユーザーが `/api/boards` 以下を呼ぶと `401` が返る。

## 異常系

`spec/000_shared_rules.md § HTTP ステータスコード` と `§ Route Handler の入口チェック順序` に従う。

### 認証、権限、存在チェック

| 状況 | ステータス | 補足 |
|---|---|---|
| 未ログインで API 呼出 | `401` | 全 API 共通 |
| 存在しない `boardId` を指定 | `404` | 個別取得、更新、削除 API |
| 閲覧権限 (`viewer` 以上) がないボードを指定 | `404` | 存在有無を漏らさないため `404` に統一 |
| ボード編集、削除 API を `owner` 以外が呼ぶ | `403` | 認証済み、閲覧可の状態が前提 |

備考: 「閲覧権限がないボードを 404 とする」 のは、閲覧権限のないユーザーに対して対象ボードの存在有無を露出させないため。認証済み、閲覧可能なユーザーが権限不足の操作を呼んだ場合のみ `403` を返す。

### バリデーションエラー

| 状況 | ステータス | フィールド | メッセージ例 |
|---|---|---|---|
| `title` 未指定または空文字 | `422` | `title` | `required` |
| `title` が 100 文字超過 | `422` | `title` | `too_long` |
| `title` が文字列型でない | `422` | `title` | `invalid_type` |

### 画面レベル

- 一覧画面の API が `401` を返した場合、ログイン導線を表示する (UI 詳細は `ui-design/` で決定)。
- 詳細画面の API が `404` を返した場合、「ボードが見つかりません」 相当の表示を行う。
- API が `403` を返した場合、「操作権限がありません」 相当の表示を行う。

## 境界条件

- `title` = 1 文字 (下限ちょうど): 受け付ける。
- `title` = 100 文字 (上限ちょうど): 受け付ける。
- `title` = 101 文字: `422` を返す。
- `title` = 0 文字 (空文字): `422` を返す。
- `title` に前後の空白のみが含まれる場合: バリデーション判定は「トリム後の長さ」 で行う。トリム後が 0 文字なら `422`。
- ボード 0 件: 一覧 API は `{ items: [] }` を 200 で返す。画面は空状態を表示する。
- 同一 `title` のボードが複数存在してよい (title は一意制約なし)。
- ボード削除直後に同 ID を GET すると `404` を返す。

## バリデーション

| フィールド | ルール |
|---|---|
| `title` | 文字列。トリム後 1〜100 文字。トリム後 0 または 101 以上で `422`。|
| `id` (URL パラメータ) | 文字列。フォーマット検証は設計工程で決定 (現時点では「存在すれば取得、存在しなければ 404」)。|

作成 API では `id` / `order` / `createdAt` / `updatedAt` はクライアントから受け取らない (サーバー側で生成、設定する)。
更新 API で受け付けるのは `title` のみとする (`order` は並び替え API を将来別途定義する)。

## 権限境界

`spec/000_shared_rules.md § 権限マトリクス` に従う。ボードに閉じた表を再掲する。

| 操作 | 必要権限 | 権限不足時の挙動 |
|---|---|---|
| ボード一覧取得 (`GET /api/boards`) | `viewer` 以上 (ログイン済み) | 未ログイン `401` |
| ボード詳細取得 (`GET /api/boards/{id}`) | 対象ボードの `viewer` 以上 | 未ログイン `401`、閲覧不可 `404` |
| ボード作成 (`POST /api/boards`) | ログイン済みユーザー (作成者が `owner` となる) | 未ログイン `401` |
| ボード編集 (`PATCH /api/boards/{id}`) | 対象ボードの `owner` | 未ログイン `401`、`owner` 以外 `403`、閲覧不可 `404` |
| ボード削除 (`DELETE /api/boards/{id}`) | 対象ボードの `owner` | 未ログイン `401`、`owner` 以外 `403`、閲覧不可 `404` |

## 非機能要件

`spec/000_shared_rules.md § 非機能要件` に従う。ボード固有の追加要件は無し。

## 未決事項

- ボード新規作成時に作成者を `owner` として関連付ける仕組み (メンバーシップテーブル設計) は設計工程で決める。
- 閲覧可能ボードの取得を「メンバーシップテーブル JOIN」 で行うか「別経路」 で行うかは設計工程で決める。
- ボード並び替え API (`order` の更新) は本 spec の対象外とし、別 spec で扱う (初期実装では作成順の末尾追加のみをサポートする)。
- 削除確認ダイアログの文言、空状態の文言、エラー画面の文言は `ui-design/` で決める。
