# 期限機能の仕様

## 概要

本 file はカードの期限 (Due Date) の仕様を定義する。
期限はカードに対して設定 / 変更 / 解除でき、期限切れをカード上と詳細モーダル上で視覚的に区別する。
本 spec では時刻は扱わず、日付単位で管理する。
共通ルールは `spec/000_shared_rules.md`、カード仕様は `spec/003_cards.md`、カード詳細モーダルの配置は `spec/005_card_detail.md § カード詳細モーダルの拡張構造` を参照する。

## 既存仕様との関係

- 本 spec は `spec/003_cards.md` および `spec/005_card_detail.md` に対する追補である。
- `spec/005_card_detail.md § カード詳細モーダルの拡張構造` の「期限領域」 は本 spec で表示、操作方針を確定させる。
- 期限による絞り込みは `spec/008_search_filter.md` で扱う。
- `spec/000_shared_rules.md § 未決事項` の「期限機能は別 spec で決める」 を本 spec が担う。

## 対象データ

### Card エンティティへの追加フィールド

`spec/003_cards.md § 対象データ` に、以下のフィールドを追加する。

| フィールド | 型 | 説明 |
|---|---|---|
| `dueDate` | 文字列 (`YYYY-MM-DD`) / null | カードの期限。日付のみ (時刻は扱わない)。未設定は `null`。 |

- 表現形式は ISO 8601 の日付部分のみ (`YYYY-MM-DD`) を用いる。時刻とタイムゾーンは持たない。
- 期限は「その日付の 23:59:59.999 まで」 を含む扱いとし、期限切れ判定はサーバー時刻の「本日の日付」 と比較する (詳細は `§ 期限切れ判定`)。
- 期限のタイムゾーンは、判定時点のサーバー時刻を用いる。初期方針はサーバー時刻の UTC 日付 (`toISOString().slice(0, 10)` 相当) を「本日」 とする。設計工程でユーザーローカルタイムゾーンへの拡張を検討する余地を残す。

## 機能要件

### 操作: 期限の設定

- カード詳細モーダルの期限領域から実行する (`spec/005_card_detail.md § カード詳細モーダルの拡張構造`)。
- 入力項目は `dueDate` のみ (`YYYY-MM-DD` 形式の日付)。UI 上は日付ピッカーを想定する (詳細は `ui-design/`)。
- 過去日付の設定を許容する (過去の期限切れとして扱う)。
- 設定操作は対象カードの `dueDate` を更新し、`updatedAt` を更新する。

### 操作: 期限の変更

- 既に期限が設定されているカードに対して、期限領域の変更導線から実行する。
- 挙動と API は「期限の設定」 と同一 (上書き更新)。

### 操作: 期限の解除

- 期限領域の「期限を解除する」 導線から実行する。
- 対象カードの `dueDate` を `null` に更新し、`updatedAt` を更新する。

### 期限切れ判定

- 本 spec は次の判定ロジックを定義する。
  - `dueDate` が `null` の場合: 期限なし。
  - `dueDate` が本日と同一 (`dueDate == today`): 「今日が期限」。
  - `dueDate` が本日より後 (`dueDate > today`): 期限内。
  - `dueDate` が本日より前 (`dueDate < today`): 期限切れ。
- 判定はサーバー側で行うことを推奨するが、UI 側でも同一ロジックで判定できるよう API レスポンスに `dueDate` を含める。
- カード詳細モーダルでは、期限領域内で「今日が期限」 と「期限切れ」 を視覚的に区別する (詳細は `ui-design/`)。
- リスト内のカード行にも期限バッジを表示する (`ui-design/` で配置決定)。バッジ表現は「期限なし = 表示なし」 / 「期限内 = 通常表現」 / 「今日が期限 = 注意表現」 / 「期限切れ = 警告表現」 の 4 状態を持つ。

### アーカイブ済み / 削除済みカードの扱い

- `status = archived` および `status = deleted` のカードは期限切れ判定の対象外。バッジは非表示または「アーカイブ」 / 「削除済み」 の状態表示のみ (`ui-design/`)。
- 期限の設定 / 変更 / 解除は `status = active` のカードのみで可能。`archived` および `deleted` に対する API 呼出は `422` (`invalid_state`) を返す。

## 画面

- カード詳細モーダルの期限領域 (`spec/005_card_detail.md § カード詳細モーダルの拡張構造`)。
  - 期限未設定時: 「期限を設定する」 導線。
  - 期限設定時: `dueDate` を人間可読な日付表示 (書式は `ui-design/`)、期限内 / 今日が期限 / 期限切れの視覚区別、変更導線、解除導線。
- カード行 (リスト内): 期限バッジ。期限切れは警告色、今日が期限は注意色 (色の割当は `ui-design/`)。
- 期限領域は独立して編集可能 (他領域の状態を変えない)。

## API

| メソッド | パス | 用途 | 必要権限 |
|---|---|---|---|
| `PATCH` | `/api/cards/{cardId}/due-date` | カードの期限を設定 / 変更 / 解除 | 対象ボードの `member` 以上 |

- レスポンス形式と認証チェック順序は `spec/000_shared_rules.md` に従う。
- レスポンスは更新後の `Card` オブジェクト。
- リクエスト body は `{ "dueDate": <文字列 | null> }`。文字列は `YYYY-MM-DD` 形式 (設定 / 変更)、`null` は解除。
- カード一覧および詳細 API (`spec/003_cards.md § API`) のレスポンスにも `dueDate` フィールドを含める。

## 受入条件

- [ ] `member` 以上のユーザーがカード詳細モーダルから `YYYY-MM-DD` 形式の日付を入力して期限を設定すると、モーダルとカード行に日付が表示される。
- [ ] 既に期限が設定されているカードに対して別の日付で更新すると、上書き保存される。
- [ ] `member` 以上のユーザーが期限領域から解除を実行すると、`dueDate` が `null` になり、モーダルとカード行から日付表示が消える。
- [ ] `dueDate` が本日と同一のカードは「今日が期限」 の視覚区別で表示される。
- [ ] `dueDate` が本日より前のカードは「期限切れ」 の視覚区別で表示される。
- [ ] `dueDate` が本日より後のカードは通常表現で表示される。
- [ ] `dueDate` が `null` のカードには期限バッジが表示されない。
- [ ] `viewer` ロールのユーザーが期限更新 API を呼ぶと `403` が返る。
- [ ] 未ログインユーザーが期限更新 API を呼ぶと `401` が返る。
- [ ] 存在しない `cardId` を指定した API 呼出は `404` を返す。
- [ ] `YYYY-MM-DD` 以外の形式で `dueDate` を指定すると `422` (`invalid_format`) が返る。
- [ ] `dueDate` に日付として不正な値 (`2026-02-30` 等) を指定すると `422` (`invalid_date`) が返る。
- [ ] `status = archived` または `status = deleted` のカードに対して期限更新 API を呼ぶと `422` (`invalid_state`) が返る。
- [ ] 過去日付の設定は成功し、期限切れとして表示される。

## 異常系

`spec/000_shared_rules.md § HTTP ステータスコード` と `§ Route Handler の入口チェック順序` に従う。

### 認証、権限、存在チェック

| 状況 | ステータス | 補足 |
|---|---|---|
| 未ログインで API 呼出 | `401` | 期限更新 API |
| 存在しない `cardId` を指定 | `404` | 期限更新 API |
| 閲覧権限 (`viewer` 以上) のないボード配下のカードを指定 | `404` | 存在有無を漏らさないため `404` に統一 |
| `viewer` ロールが期限更新 API を呼ぶ | `403` | 認証済み、閲覧可の状態が前提 |

### バリデーションエラー / 状態エラー

| 状況 | ステータス | フィールド | メッセージ例 |
|---|---|---|---|
| `dueDate` が `YYYY-MM-DD` 形式でない | `422` | `dueDate` | `invalid_format` |
| `dueDate` が日付として不正 (`2026-02-30` / `2026-13-01` 等) | `422` | `dueDate` | `invalid_date` |
| `dueDate` が文字列でも `null` でもない | `422` | `dueDate` | `invalid_type` |
| `dueDate` フィールド未指定 (body 全体が空) | `422` | (body 全体) | `required` |
| 対象カードが `archived` または `deleted` 状態 | `422` | (body 全体) | `invalid_state` |

### 画面レベル

- 期限領域の API が `403` を返した場合、「操作権限がありません」 相当の表示を行う。
- 期限領域の API が `422` を返した場合、期限領域内にフィールド別エラーメッセージを表示し、操作前の期限を保持する。
- 期限領域の API が `404` を返した場合 (対象カードが他ユーザーにより削除された等)、モーダルを閉じる。

## 境界条件

### `dueDate` の日付範囲

- 本日 (サーバー時刻の本日): 受け付ける。判定は「今日が期限」。
- 昨日: 受け付ける。判定は「期限切れ」。
- 明日: 受け付ける。判定は「期限内」。
- 遠い過去 (例: `1970-01-01`): 受け付ける。判定は「期限切れ」。
- 遠い未来 (例: `9999-12-31`): 受け付ける。判定は「期限内」。
- 上限、下限の制約は設けない (Prisma の日付型が扱える範囲を前提とする)。

### 形式

- `YYYY-MM-DD` (半角、ゼロパディング): 受け付ける (例: `2026-07-12`)。
- `YYYY/M/D` / `YYYY-MM-DDTHH:MM:SS` / タイムゾーン付き / 時刻付き: `422` (`invalid_format`)。
- 存在しない日付 (`2026-02-30` / `2025-04-31` / `2026-13-01`): `422` (`invalid_date`)。
- 空文字 `""`: `422` (`invalid_format`)。
- `null`: 期限解除として受け付ける。

### 状態遷移との整合

- `status = active` のカードへの期限設定 / 変更 / 解除: 200 で成功。
- `status = archived` のカードへの期限設定 / 変更 / 解除: `422` (`invalid_state`)。
- `status = deleted` のカードへの期限設定 / 変更 / 解除: `422` (`invalid_state`)。
- アーカイブ操作 (`spec/004_card_movement_archive_restore.md`) を行っても `dueDate` は保持する。復元時にそのまま復活する。

### 期限切れ判定の日境界

- 判定の「本日」 はサーバー時刻を用いる。UTC 換算で `YYYY-MM-DD` を取り出す (初期方針)。
- サーバー時刻とクライアント時刻の乖離により UI 表示上「今日が期限」 と「期限切れ」 の判定が異なる場合、サーバー側の判定を正とする。API レスポンスに判定結果を含めるかは設計工程で決める。

## バリデーション

| フィールド | ルール |
|---|---|
| `dueDate` | 文字列 (`YYYY-MM-DD` 形式) または `null`。形式外は `invalid_format`、日付として不正は `invalid_date`、型不一致は `invalid_type`。 |
| `cardId` (URL パラメータ) | 文字列。存在しないと `404`。閲覧権限がないと `404`。 |

- 期限更新 API では `id` / `createdAt` / `updatedAt` はクライアントから受け取らない。
- 期限更新 API で受け付けるのは `dueDate` のみ。

## 権限境界

`spec/000_shared_rules.md § 権限マトリクス` に本 spec 追加操作を統合した表。

| 操作 | 必要権限 | 権限不足時の挙動 |
|---|---|---|
| 期限更新 (`PATCH /api/cards/{cardId}/due-date`) | 対象ボードの `member` 以上 | 未ログイン `401`、`viewer` は `403`、閲覧不可 `404` |
| 期限を含むカード取得 (既存 `GET /api/cards/{cardId}` / `GET /api/lists/{listId}/cards`) | 対象ボードの `viewer` 以上 | 未ログイン `401`、閲覧不可 `404` (既存挙動、レスポンスに `dueDate` を含める) |

## 非機能要件

`spec/000_shared_rules.md § 非機能要件` に従う。本 spec 固有の要件は次の通り。

### 性能

- 期限更新 API は書き込み API として P95 300ms 以内。
- 期限を含むカード一覧 API は既存の P95 200ms 以内目標を維持する (期限バッジ表示のための追加負荷はレスポンス構造の拡張のみ)。

### 運用 (操作ログ)

- 期限設定、変更、解除の各操作について、操作種別 (`card_due_date_update`)、対象識別子 (`cardId`)、対象ボード識別子 (`boardId`)、操作ユーザー識別子 (`userId`)、遷移前 `dueDate`、遷移後 `dueDate`、タイムスタンプを操作ログに残す。

### セキュリティ

- `constitution.md § セキュリティ` に従う。追加要件なし。
