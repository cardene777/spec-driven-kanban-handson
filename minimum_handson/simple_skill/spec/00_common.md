# 共通ルールの仕様

## 概要

最小構成のカンバンアプリ全体で共通する、画面構成・エラー形式・タイトル検証・並び順・判定順序のルールを定める。個別の仕様（ボード / リスト / カード / カード編集）はこの共通ルールを前提とする。

## 機能要件

### FR-001 2画面構成

- 入力 なし
- 条件 常時
- 出力 ボード一覧画面（`app/page.tsx`）とボード詳細画面（`app/boards/[id]/page.tsx`）
- 振る舞い アプリはこの2画面で完結する。ボード一覧の各ボードカードから `/boards/[id]` へ遷移できる。

### FR-002 データ永続化

- 入力 各リソースの作成・更新操作
- 条件 常時
- 出力 SQLite に保存されたデータ
- 振る舞い データは Prisma 7 + SQLite で永続化する。

### FR-003 サーバ側データ取得とクライアント側更新

- 入力 ボード詳細画面の初期表示、および作成後の一覧更新
- 条件 常時
- 出力 画面に表示されるボード・リスト・カード
- 振る舞い `app/boards/[id]/page.tsx` は repository から対象のボード・リスト・カードを取得する。GET API はクライアント側の一覧更新（作成後の再取得）に使う。

## 異常系

| ID | 条件 | HTTP ステータス | レスポンス |
|---|---|---|---|
| E-000 | 入力タイトルがトリム後に空文字、または上限超過 | 400 | `{ "error": { "code": "VALIDATION_ERROR", "message": "..." } }` |
| E-001 | 親または対象リソースが存在しない | 404 | `{ "error": { "code": "NOT_FOUND", "message": "..." } }` |

## 境界条件

- タイトルはトリム後の文字数で判定する（前後の半角・全角空白、タブ、改行を除去してから数える）
- 存在しない親リソースへの作成は、body に不正なタイトルがあっても 404 を優先する

## バリデーション

| フィールド | 必須 | 制約 |
|---|---|---|
| title（共通ルール） | はい | 前後の半角・全角空白・タブ・改行を除去 → 1文字以上・上限以下を検証 → トリム後の値を保存。上限はリソースごとに定める |

## エラー形式

- すべてのエラー応答は `{ "error": { "code": "...", "message": "..." } }` に統一する
- `code` は `VALIDATION_ERROR`（400）または `NOT_FOUND`（404）

## 判定順序

- 対象リソースが無い場合は 404 を先に返す
- 対象が存在する場合だけ入力を検証し、不正なら 400 を返す

## 並び順（共通）

- 親内に0件なら `order` は 0、以後は同じ親内の最大 `order` + 1 を割り当てる
- 同じ親内で `order` を重複させない
