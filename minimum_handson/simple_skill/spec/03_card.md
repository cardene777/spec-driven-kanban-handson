# カードの仕様

## 概要

ボード詳細画面で、各リストに属するカードの一覧表示と新規追加を行う。共通ルールは spec/00_common.md に従う。カードのタイトル編集は spec/04_card_edit.md で扱う。

## データモデル

- Card は `id`、`title`、`description`、`order`、`listId`、`createdAt` を持つ。
- `description` は省略可能（nullable）。
- Card は List に属する（`listId`）。

## 機能要件

### FR-301 カード一覧表示

- 入力 対象リスト
- 条件 ボード詳細画面を開いたとき
- 出力 各リスト内のカード一覧
- 振る舞い 同じリスト内では `order` の昇順で並べて表示する。

### FR-302 カード追加フォームの表示

- 入力 リスト末尾の「カード追加」ボタンの押下
- 条件 ボード詳細画面
- 出力 タイトル入力フォーム
- 振る舞い 各リストの末尾に「カード追加」ボタンを置き、押すとタイトル入力フォームが表示される。

### FR-303 カード追加

- 入力 タイトル（文字列）
- 条件 フォーム送信時
- 出力 作成された Card
- 振る舞い トリム後のタイトルを検証し、有効なら Card を作成する。`order` は同じリスト内に0件なら0、以後は最大 `order` + 1。作成後、リストの末尾にカードが追加されて見える。

### FR-304 カード一覧取得 API

- 入力 リスト ID（パス）
- 条件 GET `/api/lists/[id]/cards`
- 出力 対象リストのカード配列（`order` 昇順）
- 振る舞い 対象リストのカードを `order` 昇順で返す。クライアント側の一覧更新に使う。

### FR-305 カード作成 API

- 入力 リスト ID（パス）、`{ "title": string }`
- 条件 POST `/api/lists/[id]/cards`
- 出力 作成された Card
- 振る舞い 対象リストの存在を先に確認し、存在すればトリム後のタイトルを検証して Card を作成する。`description` は省略可能。

## 異常系

| ID | 条件 | HTTP ステータス | レスポンス |
|---|---|---|---|
| E-301 | 対象リストが存在しない | 404 | `{ "error": { "code": "NOT_FOUND", "message": "リストが見つかりません" } }` |
| E-302 | 対象リストは存在し、title がトリム後に空文字 | 400 | `{ "error": { "code": "VALIDATION_ERROR", "message": "タイトルは1〜200文字で入力してください" } }` |
| E-303 | 対象リストは存在し、title がトリム後に200文字超 | 400 | `{ "error": { "code": "VALIDATION_ERROR", "message": "タイトルは1〜200文字で入力してください" } }` |

## 境界条件

- 存在しないリスト ID へのカード作成は、body に不正なタイトルがあっても 404 を優先する
- タイトル トリム後 0文字 → エラー
- タイトル トリム後 1文字 → 成功
- タイトル トリム後 200文字 → 成功
- タイトル トリム後 201文字 → エラー

## バリデーション

| フィールド | 必須 | 制約 |
|---|---|---|
| title | はい | 前後の半角・全角空白・タブ・改行を除去してから 1〜200文字。トリム後の値を保存する |
| description | いいえ | 省略可能（nullable） |
| listId | はい | 既存の List を指すこと |

## 並び順

- 同じリスト内では `order` の昇順で並べる。
- 0件なら `order` は0、以後は同じリスト内の最大 `order` + 1。同じリスト内で `order` を重複させない。
