# Simple Kanban Constitution

## プロジェクト概要

- 名前はSimple Kanbanです。
- 小規模チームがタスクをボード、リスト、カードで管理するWebアプリです。
- 仕様、設計、実装、テスト、レビュー、ドキュメントを分けて管理します。

## 技術スタック

| 分類 | 採用技術 |
|---|---|
| フレームワーク | Next.js 16 App Router、create-next-app --webpack |
| 言語 | TypeScript |
| DB | ローカルSQLite |
| ORM | Prisma 7、adapter-better-sqlite3、prisma-client、出力generated/prisma |
| スタイル | Tailwind CSS |
| テスト | Vitest 4 |
| 依存管理 | npm |
| lint | ESLint直接実行、next lintは使わない |
| ランタイム | Node.js 20.19以上 |

## コーディング規約

- APIはNext.jsのRoute Handlerで実装します。
- データアクセスはPrismaに集約します。
- バリデーション失敗は422、未認証は401、権限不足は403、存在しないリソースは404、予期しないサーバー側エラーは500を返します。
- エラー応答は `{ "error": "<エラー名>" }` を基本とします。入力値の項目別エラーは `{ "error": "validation_error", "fields": { "<フィールド名>": "<理由>" } }` の形に統一します。
- テストは仕様の正常系、異常系、境界条件を確認できる単位で置きます。
- 認証、権限、ログなど複数機能で共有する処理は `lib/` に集約します。

## 非機能要件

### 性能

- 一覧APIの応答時間は200ms以内、書き込みAPIの応答時間は300ms以内を、ローカルSQLite・少量データを前提にした設計目標として書きます。CHAPTER 05では測定も達成判定も行いません。
### 可用性

- 稼働率の数値目標は設けません（ローカル開発環境が対象のため）。
### セキュリティ

- ローカル開発用のSQLiteを使い、機密データは扱いません。
### 運用

- 操作ログとエラーログは、あとから追跡できる形で残します。リクエスト ID を発行して両方に付与します。

## 権限ポリシー

- ロールはowner、member、viewerの3つです。
- ownerはボードの作成、編集、削除、メンバー招待、権限変更ができます。
- memberはリストとカードの作成、編集、移動、コメント投稿ができます。
- viewerは閲覧のみできます。
- 未ログインは401、権限不足は403を返します。閲覧権限のないリソースは存在有無を漏らさないため404を返します。
- API処理では「認証 → 対象存在 → 権限 → 入力検証」の順で判定します。
- 最初のBoard・List・Cardの実装では認証と権限確認を実装せず、基本APIは権限確認を通過する前提にします。`User`、`BoardMembership`、3ロールの確認、資格情報の検証、セッション管理、ログイン、招待、権限管理の画面、利用者の切り替えは、本書のハンズオンでは実装しません。操作ログは初期実装に含めます。

## 用語集

| 用語 | 英訳 | 定義 |
|---|---|---|
| ボード | Board | カンバンの最上位単位 |
| リスト | List | ボード内の列 |
| カード | Card | タスクを表す項目 |
| 担当者 | Assignee | カードに割り当てられたユーザー |
| 期限 | Due Date | カードの完了予定日 |
| コメント | Comment | カードに残す会話 |
| アーカイブ | Archive | 表示対象から外す操作 |
| 復元 | Restore | アーカイブや削除状態から戻す操作 |
| ラベル | Label | カードの分類タグ |

## 基本原則

仕様・設計・実装・検証を分離し、入力にない機能を追加しない。

## 著者確認済み追加条件

リスト削除・初期カード削除はmember以上。Card.descriptionは空文字を許可し0〜2000文字、2001文字以上は422。空文字拒否は必須titleだけ。本文外の読者回答である。

## 通常設計の採用案

Prisma 7、adapter-better-sqlite3、prisma-client generator（出力generated/prisma）を採用。ファイルはapp/、lib/、tests/。IDはcuid、日時はUTC ISO 8601、orderは親ごとの0始まり連番、削除時は子をcascade。初期Card削除は物理削除。Section 03で仕様のみ変更する。

## 権限テーブル

### ロール
| ロール | 説明 | デフォルト権限 |
|---|---|---|
| owner | ボード管理者 | member操作＋ボード管理・招待・権限変更 |
| member | チーム参加者 | リスト・カード書込、移動、削除、コメント投稿 |
| viewer | 閲覧者 | 閲覧のみ |

### 操作と必要権限

| 操作 | 必要権限 |
|---|---|
| 閲覧 | viewer以上 |
| Board作成・編集・削除、招待・ロール変更 | owner |
| List/Card作成・編集・並び順・移動・初期削除 | member以上 |
| コメント投稿 | member以上 |
割当時のデフォルトロールは未決（初期実装に利用者管理なし）。

### 権限チェックの実装方針

初期APIの認証・権限は通過前提。追加仕様のsoft削除もmember以上、purgeはownerのみ（Section 03本文回答）。実ロール解決は未実装。
